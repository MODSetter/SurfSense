# Egress

Nothing is meant to leave the machine until the user allows where it goes. Before a call reaches the network, the backend names its destination and calls `egress.require()`, which refuses with `403 egress_disabled` unless the user has allowed that destination, so a refused call never opens a connection. A destination is a host, off by default, and loopback is not egress; the calls that escape the check are listed under Known gaps. The renderer turns a refusal of something the user just did into a consent dialog, and never asks on a background read.

**Code:** [`surfsense_local/backend/modules/egress/`](../../surfsense_local/backend/modules/egress/), [`surfsense_local/frontend/src/features/egress/`](../../surfsense_local/frontend/src/features/egress/), [`surfsense_local/frontend/src/lib/api.ts`](../../surfsense_local/frontend/src/lib/api.ts)
**Decisions:** [ADR 0017](../adr/0017-egress-off-by-default.md), [ADR 0070](../adr/0070-opt-in-id-less-update-checks-and-usage-statistics.md)

## Destinations

| Destination | Host | Covers |
|---|---|---|
| `host:huggingface.co` | `huggingface.co` | searching Hugging Face and reading a repo on the model screen, downloading a GGUF for the llama.cpp runtime, and downloading weights for the bundled sd-server |
| `host:plugins.surfsense.com` | `plugins.surfsense.com` | fetching the third-party plugin registry and its icons ([plugin registry](plugin-registry.md)), and SurfSense's own plugins on the [plugin host](plugin-host.md) |
| `host:api.surfsense.com` | `api.surfsense.com` | SurfSense's license server: fetching a renewed license file, which sends the license key ([license](license/app.md#renewal)), and downloading the job packs a license includes, which sends the key, the job's code, the version installed and the app's job runners ([jobs](jobs.md#delivery)); each also sends the IP address and `User-Agent: SurfSense`. Settings › Network names it License server |
| `host:<hostname>` | that host | everything sent to one remote OpenAI-compatible connection: probes, model lists, tests, chat, image generation; or to one plugin's server: listing its tools and calling them; or to its authorization server: signing in and refreshing |
| `host:<site>` | a site a link added from the web or read by the agent is on, or a site it redirects to | reading that page on the user's own connection: its address and the IP address ([sources from the web](web-sources.md), [agent](agent.md#surfsenses-tools)) |
| `host:www.youtube.com` | `www.youtube.com` | reading a video's transcript and facts, for a video link on any YouTube host |
| `host:searxng.surfsense.com` | `searxng.surfsense.com`, or the SearXNG server the user names in Settings › Network | searching from Add from the web or by the agent: the query and the IP address |
| `host:downloadarchive.documentfoundation.org` | `downloadarchive.documentfoundation.org` | downloading the Office pack, The Document Foundation's LibreOffice build, when the user turns Office support on ([office pack](office-pack.md)) |

There is one row per host by construction: the key is the hostname, so a destination cannot exist twice under two names, and the user is asked about the host rather than about each errand sent to it. `host:huggingface.co`, `host:plugins.surfsense.com` and `host:api.surfsense.com` are built in (`BUILT_IN` in `modules/egress/service.py`), so they are listed before anything names them. The Hugging Face question names search and downloads, search first because it is the widest: searching sends what the user types, as they type it; downloading sends the name of the model they chose; both send their IP address, and neither sends chats or documents. A page-read question that names `huggingface.co` adds that allowing turns search and downloads on too, since model search asks only while the row is off. The license server's dialog names both of its errands the same way, a renewed file and the license's job packs, whichever one asks.

State is one table, `egress_destinations`: a row per destination with `enabled`, false by default, and `last_call_at`, which every allowed call stamps. `GET /egress` lists the built-in destinations, one `host:` row per non-loopback host among the stored connections, off when never allowed, and every other `host:` row, such as a host an image endpoint named. `PUT /egress` turns the destinations it lists on or off, all or none: every one is checked before any is written, the request's one transaction commits them together, and anything that is not a `host:` name or built-in destination answers 422 with nothing changed. Settings › Network sends a list of one; a consent question sends every host it named ([`modules/egress/router.py`](../../surfsense_local/backend/modules/egress/router.py)). Deleting the last connection to a host deletes that host's row (`forget_if_unused()`), so a later connection there is asked about again; a host another connection still uses keeps its grant, and a built-in destination is never dropped.

`host_destination()` returns no destination for `localhost` or a loopback address, so a model server on the same machine needs no consent and has no row. A server elsewhere on the LAN is a destination like any other.

A plugin's hosts are asked about before it connects: the refusal carries `hosts`, every host still to allow, and `purpose: "plugin"`, which the prompt words its question by, saying the host gets what a tool is sent rather than every chat. A refused plugin host with no row is recorded off, so Settings › Network lists it ([plugins](plugins.md)). An OAuth plugin's authorization server is asked about the same way, once discovery names it and before any request reaches it.

Add from the web asks with `purpose: "web_page"` about the sites a click reads, saying each gets the page's address and the IP address, and with `purpose: "web_search"` about the SearXNG server, saying it gets the search. Both add that an address or a search the agent writes can carry words from the user's chats or files, but nothing else from them. A `web_page` question is worded as a page read even for a host with another errand, such as `huggingface.co` or `platform.claude.com`; one naming `huggingface.co`, first or among its hosts, adds that allowing also turns on model search and downloads there, and that searching sends what the user types as they type it. For `searxng.surfsense.com` the question adds that SurfSense runs it, and Settings › Network names that row Web search ([`features/egress/api.ts`](../../surfsense_local/frontend/src/features/egress/api.ts), [sources from the web](web-sources.md)).

Fetching the registry is refused with `purpose: "plugin_registry"`, and its prompt says the list is fetched from `plugins.surfsense.com`, sending the IP address and nothing else, and that SurfSense's own plugins run on the same host, so the one answer covers both: using them sends what each tool needs and, for the paid ones, the license key, so the host can check it. A `plugin` question that names `plugins.surfsense.com` says the same about the license key ([`features/egress/api.ts`](../../surfsense_local/frontend/src/features/egress/api.ts)).

## Where the check runs

`egress.require(session, destination)` raises `EgressDeniedError` when the row is missing or off, and `api/main.py` turns that into a `403` whose `detail` carries `code: "egress_disabled"`, the `destination`, its `host`, `hosts` (every host still to allow, `host` first), `purpose` when the host alone does not say what the call is for (`plugin`, `plugin_registry`, `claude_plan`, `job_packs`, `web_page` or `web_search`), and a message. The check sits in front of each call site, in whichever process makes the call:

| Call | Where | Destination |
|---|---|---|
| Probing a connection when it is created or updated, listing its models, running its chat and image tests | `modules/llm/connections/router.py` | `host:` |
| Choosing a remote model | `modules/llm/selection.py`, through `allowed_connection()` | `host:` |
| Checking a connection's rows against its live listing | `GET /llm/catalog/remote/connections/{id}` in `modules/llm/catalog/remote/router.py`, through `allowed_connection()` | `host:` |
| Chat and Studio generation, text or image, through a remote connection | `_connection()` in `modules/llm/resolution.py` | `host:` |
| The agent's turns, which opencode sends to SurfSense's model endpoint and SurfSense forwards to a remote connection | `address_selected_model()` in `modules/agent/model_endpoint/model_address.py`, through `allowed_connection()`; a refusal answers opencode with a `403` whose message names the host | `host:` |
| Adding a plugin by URL, before its server is contacted | `POST /plugins/custom` in `modules/plugins/routes.py`, through `refused_hosts()` | `host:` |
| Connecting a plugin from the registry, for every host its entry lists | `POST /plugins/registry/{id}` in `modules/plugins/lists/registry/routes.py`, through `refused_hosts()` | `host:` |
| Fetching the registry, its signature and its icons | `GET /plugins/registry` and `POST /plugins/registry/{id}`, through `registry_refusal()` in `modules/plugins/lists/registry/registry_consent.py`; never while third-party plugins are off, and not in an unpackaged build, which reads the checkout | `host:plugins.surfsense.com` |

| Searching from Add from the web | `POST /workspaces/{id}/documents/web/search`, through `refused_search_host()` in `modules/documents/web_sources/link_consent.py` ([sources from the web](web-sources.md)) | `host:` the SearXNG server's |
| Adding links from the web, and retrying one | `POST /workspaces/{id}/documents/web` and `POST /workspaces/{id}/documents/{document_id}/retry`, through `refused_link_hosts()` and `refused_pull_hosts()` in the same file, for every host the reads start on, and the one a site moved a page to | `host:` each site's, `host:www.youtube.com` |
| Reading a page or a video | the queued pull, `_host_check()` in `modules/documents/web_sources/background_pull/pull.py`, before every host it contacts, each redirect hop included; it fails rather than asking | `host:` each site's, `host:www.youtube.com` |
| The agent's web tools: a search, a page, a video | each call through the tool endpoint, `require_hosts()` and `host_check()` in `modules/agent/tool_endpoint/web_reach.py`, before every host, each redirect hop included; a host not allowed is recorded off and named in the result, and the thread's step offers the question on a click ([agent](agent.md#surfsenses-tools)) | `host:` the SearXNG server's, each site's, `host:www.youtube.com` |
| Downloading a GGUF | `POST /llm/installs` in `modules/llm/catalog/local/install_jobs/router.py`, checked before the job starts | `host:huggingface.co` |

| Downloading sd-server weights | `POST /llm/installs`, the same job as chat models | `host:huggingface.co` |
| Downloading the Office pack | `POST /runtime-packs/office/install` in `modules/runtime_packs/office/router.py`, checked before the install starts | `host:downloadarchive.documentfoundation.org` |
| Fetching a renewed license file, when the user checks in Settings or on the Jobs screen and in the app's own daily check | `refresh_license()` in `modules/license/renewal/license_refresh.py`, through `refused_named_host()`; `POST /license/refresh` answers a refusal as `refresh_egress_blocked`, with the fields of `egress_disabled`, which the check turns into the consent question; the daily check logs it and asks nothing ([license](license/app.md#renewal)) | `host:api.surfsense.com`, or a mirror's host |
| Downloading a license's job packs: Download and Check for updates, the frontend's call after a license with jobs is added, replaced or renewed, and the app's own checks at startup, once a day and once a run that held a check back ends | `deliver_packs()` in `modules/jobs/packs/delivery/deliver.py`, through `refused_named_host()`, when some code asked for is in the license and one a request may carry: for `POST /job-packs/download` even when a run holds back every such code, since the check made once the run ends is the app's own and never asks, and for the app's own checks only when such a code is not held back; `POST /job-packs/download` answers a refusal as `403 egress_disabled` with `purpose: "job_packs"`, after its planning commit, which `request()` turns into the consent question; the app's own checks log it and ask nothing ([jobs](jobs.md#delivery)). Allowed, only a call that sends a code stamps the last call, so a person's request that runs hold back entirely stamps none | `host:api.surfsense.com`, or a mirror's host |

The GGUF download runs inside the API (`modules/llm/providers/llamacpp/download.py`) instead of through llama-server's own fetch. llama-server is a second process the app does not proxy, so an in-process fetch is the only place the check can hold.

## Not egress

- A picture a connected image model returns as a link: it is fetched as part of that connection, its redirects included, with no decision of its own ([ADR 0078](../adr/0078-a-picture-a-connected-model-returns-is-fetched-with-its-connection.md)). Every request asks for the picture itself (`response_format: "b64_json"`), so most providers send no link at all; where one is sent, the provider chose its host, often another site's storage, as DALL·E's on Azure. The fetch sends no bearer token, no prompt and no document, and takes HTTP(S) only ([`image_response.py`](../../surfsense_local/backend/modules/llm/providers/openai_compatible/image_response.py)).

- llama-server and sd-server, which the backend reaches on `127.0.0.1`.
- The worker's `POST /internal/events` to the API, and Electron polling the API: `/health` at startup, the image runtime every few seconds.
- App updates. electron-updater runs in the Electron main process, out of reach of `egress.require()`, so it is gated by the `automatic` preference in `updates.json`, by the first-run Privacy choices step and by consent in the renderer instead ([updates](updates.md)). Settings › Network shows it as the App updates row, host `updates.surfsense.com, falls back to github.com`, or the admin policy's mirror alone. A check sends `updates.surfsense.com` the IP address, `User-Agent: SurfSense`, the app's version, its platform and its OS, and no ID; if that host fails, it asks github.com directly with only the IP address and that user agent ([what a check sends](updates.md#what-a-check-sends)). Installers download from GitHub, whose download host on `githubusercontent.com` also sees the IP address, or from the mirror an admin policy names, and a downloaded update installs on restart, or the next time the user quits.
- Usage statistics. Electron main sends them too, to `usage.surfsense.com`, and only once the user opted in, in the first-run step or in Settings: at most one report accepted a UTC day, from up to three tries, and in the install's first week one more each time setup reaches a new step, at most four more accepted; a setup report that fails is tried again later, at most three times per step per UTC day, an hour apart. `DO_NOT_TRACK=1`, `SURFSENSE_NO_TELEMETRY=1` or an admin policy forces them off. Settings › Network shows them as the Usage statistics row, with the time of the last report as its last call. Every value in a report is a range, a flag or a fixed word, and none is an ID ([usage statistics](usage-statistics.md)). The loopback `GET /usage-statistics/summary` that Electron main reads them from is not egress.
- Links. The main process refuses new windows and `https:` navigations inside the app, and any navigation of a frame inside it but to `about:srcdoc` or `about:blank` (`electron/src/main/framed-navigation.ts`), and hands a URL on `surfsense.com` or `www.surfsense.com`, under `github.com/MODSetter/SurfSense`, the project's Discord invite, an OpenRouter page shaped `/<author>/<model>` (where OpenRouter names a speech model's voices), or a plugin's OAuth authorization page, recognised on any host by its query (an S256 PKCE code request with SurfSense's `state` and one of its two callbacks), to `shell.openExternal` (`electron/src/main/external-url.ts`); that request is the browser's. Two more reach the browser, each by its own bridge call and never by `window.open` or navigation: a link from content, a chat reply, a Studio document or a tool's result, that the user confirmed in the app's link popup ([`external-link-dialog.tsx`](../../surfsense_local/frontend/src/features/external-links/external-link-dialog.tsx)), which names its host, shows the whole address, and warns when the address carries more than 100 characters after its path, room for the conversation; any `https` page, never another scheme or an address with a user name or password (`confirmedExternalUrl`). And a listed plugin's homepage or privacy policy, opened on a click with no popup: the page names the plugin and the page, and the main process opens the address the registry lists for it, read from the app's API, never one the page passes (`electron/src/main/plugin-page-url.ts`). Report issue opens one such link, a GitHub bug form with the user's description in it; its session log goes to the clipboard, never into the link ([issue reports](issue-reports.md)).
- Docling. Packaged Python sidecars run with `HF_HUB_OFFLINE=1` (`sidecars/python.ts`) and parse with the bundled parser pack ([packaging](packaging.md)). [`test_parsing.py`](../../surfsense_local/backend/tests/integration/worker/test_parsing.py) converts a scanned PDF and images from the parser pack with every outbound connection refused and an empty Hugging Face cache; it runs from source and skips where the pack is not staged.
- Spellchecking. Chromium fetches a Hunspell dictionary from Google's CDN (`redirector.gvt1.com/edgedl/chrome/dict/`) for each language in a session's spellchecker list, when the session is created. Measured on Electron 44.2.0 on Linux, `webPreferences.spellcheck: false` and `setSpellCheckerEnabled(false)` do not stop it, and `webRequest` never sees it. The main process empties the list on `session-created`, before the app is ready ([`spellcheck.ts`](../../surfsense_local/electron/src/main/spellcheck.ts)), and no request is made after that. So Windows and Linux have no spellchecking. macOS uses the OS spellchecker, downloads nothing and ignores the call, so it keeps working there. Not measured on Windows, which runs the same code.
- Licenses. The app verifies license files offline and never contacts Keygen ([license](license/app.md)); `keygen` is refused by `PUT /egress` as unknown. Fetching a renewed file and downloading a job pack are egress, to the license server, above; importing a job pack from a file sends nothing ([jobs](jobs.md#delivery)).

## Asking for consent

`request()` in `lib/api.ts` catches `egress_disabled` on a non-GET request and hands it to `EgressPrompt`, which shows that destination's copy. A refusal naming several hosts in `hosts` is one question: the copy names the others, and Allow enables every one of them in one `PUT /egress`, so a failed Allow enables none, before the request is retried once; Cancel rethrows the refusal. A Claude plan's refusal, `purpose: "claude_plan"`, says what each of its two hosts gets ([`features/egress/api.ts`](../../surfsense_local/frontend/src/features/egress/api.ts)). The method stands in for "the user just did something", a `ponytail:` simplification, because reads also run unattended at boot and must never raise a dialog.

A refused GET therefore surfaces as an error without a prompt.

One question covers one user action: it names every host that action may reach, including a host that background work started by it reaches, which no dialog could ask about later, and leaves a host only a later action reaches to that action's own question ([ADR 0060](../adr/0060-one-consent-question-per-user-action.md)). Only hosts SurfSense names are asked about; a host a program it runs tries on its own is refused.

Studio resolves its model in the worker, where no dialog can reach the user, so a job whose connection host is off fails with the refusal as its reason. Choosing a remote model already requires its host, so this happens only after the user turns the host off again.

`askEgress()` in `features/egress/ask-egress.ts` raises the same dialog without a refused request, or for a refusal `request()` does not ask about, in three places:

- **Updates**, because their call is not the backend's to refuse: Check now asks while `automatic` is off, naming `updates.surfsense.com` and its GitHub fallback, or the policy's mirror alone (`purpose: "update_mirror"`), or, under an Electron main without the privacy bridge, GitHub's releases (`purpose: "github_releases"`), and Allow turns it on. A policy that turns updates off leaves nothing to ask. A new install answers the same question, and the one about usage statistics, in onboarding's Privacy choices step instead, before any check runs.
- **Model search**, because the answer is wanted before the request: focusing the search box asks while `host:huggingface.co` is off, once per visit to the screen, so a refused search is not the first news that search is off. After Cancel, search says it needs `huggingface.co`, while curated and installed models keep working.
- **Renewal**, because its refusal carries the license route's own code, `refresh_egress_blocked`, rather than `egress_disabled`: Check for renewal, in Settings › License or on the Jobs screen, asks with the refusal's fields and `purpose: "license_refresh"`, and checks once more on Allow ([`use-license-refresh.ts`](../../surfsense_local/frontend/src/features/license/use-license-refresh.ts)). After Cancel, the row says where to allow the host.

The license server has one question for both of its purposes, matched by `purpose` `license_refresh` or `job_packs`, or by the destination `host:api.surfsense.com`, and labelled License server. Its title follows the purpose: "Allow checking for license renewals?" for a renewal, "Allow downloading your jobs?" for a job pack download, which `request()` asks about as it does any refused action, and "Allow reaching SurfSense’s license server?" otherwise. Its body names what each errand sends, the license key and the IP address, and for a job pack also the job's code, the version installed and the kinds of job the app can run, and that allowing also lets the app's own checks reach the host at startup and once a day, for a renewal around a Business license's end and for newer job packs while a license with jobs is active, which no dialog can ask about later ([license](license/app.md#the-daily-check), [jobs](jobs.md#delivery)). It also says that a job check that came during a run of that job is made again once the run ends.

Refused requests and `askEgress()` queue for one prompt, an app dialog (`AppDialogs` in `components/ui/app-dialog-slot.tsx`): it renders inside the innermost open dialog, so the question opens as that dialog's nested dialog and the dialog steps back behind it, or on its own when none is open. Questions still waiting when no prompt is mounted are answered no.

Settings › Network lists the App updates and Usage statistics rows and every destination with its host and last call. Unticking one refuses the next call outright. A row an admin policy or `DO_NOT_TRACK` holds off is disabled and says why.

## Known gaps

- Document scripts, Studio's Office formats and the agent's, run model-written code in the script runner's process, and that code can open connections of its own ([studio](studio.md#script-documents)).
- The Office pack's download is allowed by its host, `downloadarchive.documentfoundation.org`, which redirects to one of TDF's mirrors; the mirror sees the user's IP address and is not asked about ([office pack](office-pack.md)).
