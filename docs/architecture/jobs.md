# Jobs

A job pack adds B2B jobs to the app: a security questionnaire filled in from the firm's own policies is the first. The pack is data only (prompts, header words, answer rules and the job's skill), so installing one starts no process; the app's runner reads it, asks the selected model one question at a time, checks every answer against the sources, and writes a revised copy of the requester's workbook. The user's file is never written. SurfSense's B2B jobs are paid plugins ([ADR 0067](../adr/0067-b2b-jobs-ship-as-paid-plugins.md)): their packs live outside this repository, while everything here is the shared job infrastructure, free under Apache-2.0.

**Code:** [`surfsense_local/backend/modules/jobs/`](../../surfsense_local/backend/modules/jobs/), [`worker/studio/job_run/`](../../surfsense_local/backend/worker/studio/job_run/), [`tool_endpoint/run_job.py`](../../surfsense_local/backend/modules/agent/tool_endpoint/run_job.py), the Excel engine's inspection ([studio](studio.md#revised-copies)), and the eval harness in [`scripts/job_eval/`](../../surfsense_local/backend/scripts/job_eval/).
**Decisions:** [ADR 0067](../adr/0067-b2b-jobs-ship-as-paid-plugins.md). The design it follows is [08](../../plans/community-local/seo/08-b2b-artifact-jobs.md#what-the-agent-needs-one-engine-for-many-jobs), items 1 to 5 and 11.

## The parts

| Part | Where | Does |
|---|---|---|
| Packs | `jobs/packs/` | the manifest, the sha256 of every file, installing from a folder or a `.zip`, the paid check, the skills a pack brings |
| Runner | `jobs/workbook_rows/` | `workbook-rows/1`: finding a workbook's questions, one schema-held call per question, the checks, the engine's operations |
| Evidence | `jobs/evidence/` | the sources cut into numbered passages; all of them when they fit, else per question the best by BM25 and by the app's embedder in turn, with the passages the pack's standing queries find |
| Provenance | `jobs/provenance/quote_check.py` | whether a quote is in a source, word for word |
| Runs | `jobs/runs/`, `worker/studio/job_run/` | a run as a revised copy whose operations the Studio worker works out |
| Routes | `jobs/router.py` | the installed packs, install and remove, start and read a run |
| Agent | `tool_endpoint/run_job.py`, `opencode_config.py` | the job tool and the pack's skill in an Agentic chat |
| Evals | `scripts/run_job_eval.py`, `scripts/job_eval/` | the same runner on a pack's real-data cases, per model |

## Packs

A pack is a folder with `job-pack.json` ([`manifest.py`](../../surfsense_local/backend/modules/jobs/packs/manifest.py)): schema `surfsense-job-pack/1`, an id and a three-number version, its name, publisher and description, `access` `free` or `paid`, its licence file, its jobs, and `files`, every other file of the pack with its sha256. A job names its key, its runner (only `workbook-rows/1` today; another refuses the pack with `NEEDS_NEWER_APP`), its config file and, optionally, its skill folder, named `surfsense-job-<key>` and holding a `SKILL.md`. Paths are relative, in forward slashes, and never leave the pack.

Installing ([`install.py`](../../surfsense_local/backend/modules/jobs/packs/install.py)) copies the folder, or extracts the `.zip` (plain files at safe paths only, at most 50 MB, one top folder holding the manifest allowed), into a scratch folder under `<data>/job-packs/`, checks it, then replaces whatever version of the same pack was installed: one version per pack. The check refuses a file the manifest does not list, a listed file missing, and a file whose sha256 differs ([`integrity.py`](../../surfsense_local/backend/modules/jobs/packs/integrity.py)). Every read of the installed packs checks them again, so a pack changed on disk is left out with a log line. `scripts/job_pack.py seal` writes a folder's `files`, and `zip` packs it. Packs are not signed yet: the sha256s hold a pack together but do not say who made it. A dev build installs the folders or `.zip` files named in `SURFSENSE_LOCAL_JOB_PACKS` (separated as `PATH` is) when the API starts; a refused one is logged and the API starts anyway ([`dev_packs.py`](../../surfsense_local/backend/modules/jobs/packs/dev_packs.py)).

**Access** ([`access.py`](../../surfsense_local/backend/modules/jobs/packs/access.py)). A free pack's jobs run. A paid pack's run on an active licence whose plan is `business`, which no licence carries yet, or with `SURFSENSE_LOCAL_JOBS_UNLOCKED=1` in the API's environment, the developer switch until Business licences are issued. As every check in the app, this is honesty, not enforcement: what holds is that the licence server delivers paid packs only to a valid licence, and the pack's own terms.

## The runner

A job's config ([`config.py`](../../surfsense_local/backend/modules/jobs/workbook_rows/config.py)) is the job's content: its answers (for the questionnaire Yes, No, N/A and Needs review), which of them need a quote, the dropdown spellings each may take, the one fallback answer; the header words that name question, answer, comment, evidence and context columns; placeholder texts a requester leaves in an empty cell; sheets that are the requester's own (an evaluator's tab); the system, question and repair prompts; how a comment, an evidence cell and a free-text answer read; and the names of the two sheets it adds.

1. **The questions** ([`layout.py`](../../surfsense_local/backend/modules/jobs/workbook_rows/layout.py)). On each visible sheet the runner reads every cell as it shows, a formula by its stored result, since HECVAT shows each question through a formula over a hidden sheet. A table is the first header row within 40 rows naming a question and an answer column, whose question column averages at least 20 characters below it; failing that, the column with the most dropdown cells is the answers and the longest text to its left the questions, with comment and evidence columns taken from the nearest row above that labels the answer column. Within a table, a row whose answer cell has no dropdown, where most do, is a section heading unless it asks (a question mark, a verb asking for prose, or the requester's placeholder). A hidden row, a locked answer cell and an answer already given are skipped, each kept with its reason for the exceptions sheet. CAIQ v4.1 gives 283 questions this way and HECVAT 4.1.6 317 across its eight vendor tabs.
2. **The passages** ([`passages.py`](../../surfsense_local/backend/modules/jobs/evidence/passages.py), [`retrieval.py`](../../surfsense_local/backend/modules/jobs/evidence/retrieval.py)). Each source's text, as ingest made it, is cut into passages of about 900 characters, never across a Markdown heading, each knowing its lines and section. Every question sees all of them, in the same order, when their characters fit half the model's window at three characters a token and at most 120,000 characters; otherwise it sees its best few for the question alone (the pack says how many; the questionnaire's pack shows 24), since a row's own columns, such as CAIQ's control text, repeat the same words on every row. The best are BM25's ranking and, where the app has an embedder, the embedder's ranking by cosine, taken in turn: meaning finds a "third party" policy for a "supply chain" question, which no shared word does, and words find an exact term the embedder misses. Over the CAIQ and HECVAT dev rows the deciding passage was among the 24 shown for 34 of 48 gold Yes answers by BM25 alone and 36 with both in turn; chat's own blend of cosine and term coverage found 32. A passage is indexed with its document's title as well as its section and words, since a policy is named for what it covers: without the title, half of CAIQ's gold Yes answers never saw their deciding passage. A pack may also name standing queries, whose best passages (one each unless the pack says more, by the same ranking; a second pick was often off the subject) every question is shown, first and under the pack's label when it gives one: the questionnaire's ask how the firm approves and reviews its policies and how it publishes them, which a question about any one policy needs in words it never uses.
3. **The call** ([`ask.py`](../../surfsense_local/backend/modules/jobs/workbook_rows/ask.py)). One request per question: the job's system prompt, then the passages, then the question with its row's context and the values the cell takes, under a JSON schema of `quotes` (each a `passage` number and a `quote`), `answer` (the job's answers as an enum), `comment` and `confidence`, with no null-able types and no bounds, which not every structured-output engine takes. An answer may rest on several quotes because a question's parts often sit in different documents, such as a policy and the rule that every policy is reviewed each year; the runner keeps the first few (the pack says how many; the questionnaire's allows 3). The passages come first so a provider that reuses a prompt's start reads them once. A reply that holds no usable answer is asked again once.
4. **The checks** ([`decide.py`](../../surfsense_local/backend/modules/jobs/workbook_rows/decide.py)). Each quote counts only when it, at least 15 characters, is in a source word for word ([`quote_check.py`](../../surfsense_local/backend/modules/jobs/provenance/quote_check.py)): as a reader sees the text, case, punctuation, quotes and Markdown marks fold away and a link reads as its text, but digits and words do not, so "72 hours" never matches "24 hours" and "not encrypted" never matches "encrypted"; parts joined by "..." must each be in the same source, within 300 words of each other. A quote found nowhere is dropped, and an answer that needs a quote stands only on the quotes that are found. When none is, it is sent back once with the reason and the source sentence closest to it, if one shares most of its words, which small models paraphrase for about one quoted answer in ten; still none, the answer becomes the fallback, with `QUOTE_NOT_FOUND` and what the model said. So no "Yes" is ever written without a passage that holds its quote. A pack may also ask an answer that fell back to look once more, part by part, before it goes to a person: only a doubtful one, which quotes something, is unsure or says nothing of what is open, since those were the gold's Yes most often; a new answer then goes through the same checks. For the answers the pack names (the questionnaire's: Yes, No and N/A), the found quotes then get a second call under its own schema, asking whether together they are evidence for the answer: at least one about the very control the question asks after, and saying the firm does it ([`verify.py`](../../surfsense_local/backend/modules/jobs/workbook_rows/verify.py)). Refused, the model is told why, and which of its quotes were not found, and asked once more, to keep the answer on better evidence or give way; refused again, or a check that cannot be read, makes the answer the fallback with `NOT_SUPPORTED` and the reason, and a different answer on that turn makes it the fallback with `ANSWER_SWITCHED`, since nothing has checked the new answer (every No that Qwen gave on that turn was refused). Each row keeps a trace of every answer and check on the way, which the eval records. The quote check proves a passage exists; this checks it is evidence, which models often get wrong by quoting a related control, even when the answer itself is right. The answer is then written as the cell's own dropdown spelling (N/A as `NA` on CAIQ), or left blank when the list has none, with `NOT_ON_DROPDOWN`; a free-text cell gets the answer in words.
5. **The operations** ([`operations.py`](../../surfsense_local/backend/modules/jobs/workbook_rows/operations.py)). Each answer in its own cell, a comment and the source in the requester's comment and evidence columns where they are empty, then `add_sheet` twice: "SurfSense answers", one row per quote (one for a question with none) with its answer, what the cell got, confidence, source, section, line, quote and comment, and "SurfSense exceptions", one row per reason a person should look. A name already taken gets " (2)".

The runner is pure over files and a model ([`fill.py`](../../surfsense_local/backend/modules/jobs/workbook_rows/fill.py)), so Studio's worker and the eval harness run the same code. Questions run four at a time on a remote model and one at a time on a local one; a stop is checked between questions, never inside a call.

## Runs

`POST /workspaces/{id}/job-runs` with `job`, `document_id` (the workbook) and `source_ids` starts one ([`start.py`](../../surfsense_local/backend/modules/jobs/runs/start.py)): the job must be installed and allowed, the workbook a `.xlsx` or `.xlsm` source, and every source ready with text. The run is v1 of a revised copy of the workbook with no operations and a `job_run` record (pack, version, job, sources, `report: null`) ([`record.py`](../../surfsense_local/backend/modules/jobs/runs/record.py)). Refused, the route answers `409` with the reason.

In the Studio worker the revise path first works the run out ([`pipeline.py`](../../surfsense_local/backend/worker/studio/job_run/pipeline.py)): it loads the pack's config, reads the workbook's original and the sources' text, resolves the selected text model and its window and the active index's embedder (none before onboarding chooses one, and passages are then found by their words alone), commits, runs the runner, then stores the operations in `revision` and the report in `job_run` (the model, seconds, counts, each answer with its source and quote, the exceptions), and the engine applies them as for any revised copy. A reply may run to 8,192 tokens, since a remote connection does not turn a thinking model's thinking off. An endpoint that refuses the JSON schema, as Anthropic's OpenAI-compatible API does without `strict`, is asked by prompt from then on, with the schema written into the system message, and the reply is read leniently (quotes given as bare strings take their passage numbers from a list beside them): held to no schema and shown none, Sonnet gave bare strings and lost 5 of 15 answers on the live WISP case. A cancel stops the run between questions. A run that fails is not retried. `GET /workspaces/{id}/job-runs/{artifact}` reads its status, error and report.

`GET /job-packs` lists the installed packs with whether each may run and why not; `POST /job-packs/install` takes a folder or `.zip` path on this computer; `DELETE /job-packs/{id}` removes one.

## The agent

While a pack is installed the job tool is listed, naming the pack's jobs ([`run_job.py`](../../surfsense_local/backend/modules/agent/tool_endpoint/run_job.py), [agent](agent.md#surfsensess-tools)), and each job's skill folder joins opencode's `skills`, allowed by name ([agent](agent.md#the-configuration)). The skill tells the agent to call `surfsense_run_job` with the ticked workbook and policies, never to answer the questions itself, and to report the counts and the exceptions. The tool starts the run and waits up to 150 seconds; a longer run says it will appear in Studio.

## Evals

`scripts/run_job_eval.py run --pack <pack> --eval <eval folder> --model anthropic:<id> --model openrouter:<id>` runs a pack's cases, each a `case.json` naming a real workbook, real source files and a gold file, with each file's source and licence ([`cases.py`](../../surfsense_local/backend/scripts/job_eval/cases.py)). Sources are read as ingest reads them: Word through the app's own reader, PDF from its text layer, Markdown and text as they are. Each run writes its filled workbook and a record: questions found, accuracy over the gold cells, false Yes (a Yes the gold does not support), Yes without a quote, dropdown violations, integrity problems (a sheet moved, a cell changed outside the answers, a dropdown, protection, merge, macro, chart or medium changed, or a file openpyxl cannot open), tokens, dollars and seconds ([`score.py`](../../surfsense_local/backend/scripts/job_eval/score.py), [`workbook_integrity.py`](../../surfsense_local/backend/scripts/job_eval/workbook_integrity.py)); `report` rolls them up per case and model. Claude runs through Anthropic's Messages API with structured outputs, open models through OpenRouter with the schema required of the provider; neither falls back to another model, and Opus and Fable are refused. `--reasoning off` turns an open model's thinking off, which the app's connection does not. Passages are found with the app's bundled embedder, as on a fresh install, unless `--embedder none`. The cases and their gold live with the pack, outside this tree, and are built from real documents only. `tests/live/test_job_run_live.py` runs one case through the app itself.

## Known gaps

- Packs are checked by sha256 but not signed, and the licence server does not deliver them yet; a pack installs from a path on this computer.
- No Business licence exists, so paid packs run only under the developer switch.
- No screen starts a run or lists packs: a run starts from the agent's tool or the route.
- Scoping questions (HECVAT's REQU rows, which decide which tabs apply) are answered like any other question; nothing marks the tabs they rule out N/A.
- CAIQ's "SSRM Control Ownership" column and other required columns that are not an answer, comment or evidence column are left empty.
- An approved answer library is not built: past answers count only as another source the user ticks.
- Passages are embedded afresh for every run, about two minutes for 300 passages on a laptop's CPU; ingest's own chunk vectors are not reused, since a job cuts its passages differently.
- A model checks its own answers. Qwen3.5-9B's check refused most quoted answers, right and wrong alike, so on that model the job is precise but leaves about half of the Yes answers to a person; a checker on another model is not offered.
- Claude connections reach the job through Anthropic's OpenAI-compatible API, which takes no structured schema without `strict` and no effort setting, while the eval calls the Messages API at low effort: the live tests are what measure the app's own path.
