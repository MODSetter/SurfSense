# Studio

Studio turns a selection of sources into a deliverable: a Markdown document, a Word document, slides, a spreadsheet, a web page, a PDF, a mind map, flashcards, a quiz, a podcast, an image or an infographic. The user picks a format and sources and may add a prompt; a background job has the selected model write the content, through the API's model route ([admission](local-models/admission.md#the-model-route)), and the app renders it, as a file for ten of the twelve formats. Word and PDF take one of [two paths](#word-and-pdf) by the selected model, and PPTX and XLSX by a model-written script that runs in the [script runner](#script-documents). Each result is an ordinary `ARTIFACT` document, searchable and citable like any source, with a sidecar row for the format and the bytes. The agent's Word documents, PDFs, decks and workbooks are Studio artifacts too: [script documents](#script-documents), each version a script that SurfSense keeps and runs in a separate process. Studio's own Word documents and PDFs keep their spec the same way, and [Refine](#refine) rewrites it into the next version; the agent's are edited in its chat. An image or infographic is [edited](#editing-a-picture) the same way: its picture and an instruction go to the image editing model, and what comes back is its next version. A [revised copy](#revised-copies) is the user's own Word, Excel or PowerPoint file with the agent's edits applied by an engine, Word's as tracked changes; the user's file is never written.

**Code:** [`modules/artifacts/`](../../surfsense_local/backend/modules/artifacts/), [`worker/studio/`](../../surfsense_local/backend/worker/studio/), [`worker/document_script/`](../../surfsense_local/backend/worker/document_script/), [`frontend/src/features/studio/`](../../surfsense_local/frontend/src/features/studio/)
**Decisions:** [ADR 0003](../adr/0003-artifacts-as-documents.md), [ADR 0008](../adr/0008-two-job-queues.md), [ADR 0010](../adr/0010-studio-builders-not-sandboxes.md), [ADR 0028](../adr/0028-model-written-code-runs-with-approval.md), [ADR 0039](../adr/0039-document-scripts-run-without-approval.md), [ADR 0049](../adr/0049-prompts-grow-at-the-end.md)

The tables, `artifacts` and `artifact_files`, are in [`data-model.md`](data-model.md#artifacts-and-artifact_files).

## The job seam

[`service.py`](../../surfsense_local/backend/modules/artifacts/service.py)`::create_artifact_job(session, workspace, payload, *, tool_call_id=None)` is the one entry for every format Studio drafts. The REST route passes no `tool_call_id`, and neither does the agent's `surfsense_create_artifact`, whose call reaches SurfSense without one ([agent](agent.md#surfsenses-tools)). Explicit or agentic, same code. A script document has its own entry, below.

1. Look the format up in the catalog (`422` if unknown) and check that it is available (`409` if not, whose `detail` is `{message, code}`: the listing's reason and its `unavailable_code`). Regenerate answers the same `409`, except for a script document, which runs as stored and needs no model ([below](#script-documents)), and a file a tool made or converted.
2. Resolve the sources: at least one (`422`, code `no_sources`), all in this workspace (`422`) and all `ready` (`409`; a scope with nothing ready because its sources are still indexing is `sources_indexing`). A refusal with a code sends `detail` as `{message, code}`, like the `409` of step 1; a source named by id that is in another workspace or still indexing has none yet.
3. Validate the options with the format's `validate_options` hook. Only podcast has one; a bad brief is a `422`.
4. Create the `ARTIFACT` document, `pending` and titled with the format's label, and its `artifacts` sidecar with `generation` 1, `created_by_tool_call_id`, and the source ids, prompt and options in `artifact_metadata`.
5. Commit, then enqueue `studio_job(artifact_id)`.

Status lives on the document, not the sidecar, because ADR 0003 keeps indexing state on the `Document`. The worker moves it from `pending` to `processing` and then to `ready` or `failed`; a cancel makes it `cancelled`.

## Formats

The catalog is a tuple of thirteen `Format` rows in [`formats.py`](../../surfsense_local/backend/modules/artifacts/formats.py), computed into availability on each request and never stored.

| Key | Label | Needs | Worker path | Stored file |
|---|---|---|---|---|
| `summary` | Markdown | text_gen | `content/summary/` | `.md`, the body as a file |
| `docx` | Word | text_gen | `office/` | `.docx` |
| `pptx` | Slides | text_gen | `office/` | `.pptx` |
| `xlsx` | Spreadsheet | text_gen | `office/` | `.xlsx` |
| `html` | Web page | text_gen | `web/html/` | `.html` |
| `pdf` | PDF | text_gen | `office/` | `.pdf` |
| `mindmap` | Mind map | text_gen | `content/mindmap/` | none; the outline is the body |
| `flashcards` | Flashcards | text_gen | `content/flashcards/` | deck JSON |
| `quiz` | Quiz | text_gen | `content/quiz/` | quiz JSON |
| `podcast` | Podcast | text_gen, audio_gen | `media/audio/podcast/` | MP3 audio, or WAV without a working encoder |
| `image` | Image | image_gen, text_gen | `media/visual/image/` | the image |
| `infographic` | Infographic | image_gen, text_gen | `media/visual/infographic/` | the image |
| `comic` | Comic | image_gen, text_gen | `media/visual/comic/` | `.pdf`, the bound pages |

- The panel shows `infographic` as a type of `image`: one Image card, whose dialog chooses Image or Infographic and sends that format's key ([`picture-types.ts`](../../surfsense_local/frontend/src/features/studio/picture-types.ts)). An infographic card shows only when the catalog has no `image`. A format's own options in the dialog, the podcast brief or the picture type, come from [`format-options/`](../../surfsense_local/frontend/src/features/studio/format-options/).

- `requires_model_types` is a tuple in the order the pipeline's `render()` takes its models. A format is available when every required model type has a selection; otherwise the reason names every missing one in a fixed reading order: "Needs a chat model", "Needs an image model", "Needs an audio model", or two of them joined, as "Needs a chat model and an audio model". Naming only the first missing type made selecting it look like the gate moving to the other.
- `podcast` runs with an `audio_gen` model on this computer or on a server. The format list and the brief read the model's voices without calling it, so neither needs the server's host allowed; the job does. Opening a podcast brief without an audio model answers `409` with "Needs an audio model" and the code `needs_audio`, in the same `{message, code}` detail as a refused create. The app ships Kokoro and chooses it at startup when no audio model is chosen, so that answer needs the choice cleared since the last start, or a build without audio.cpp ([`local-models/selection.md`](local-models/selection.md)).
- Which formats are available is the server's answer to what is selected, so the panel asks again whenever the chat selection changes or the settings dialog closes, since the image model is chosen inside settings and nothing else reports it.
- An image selection can resolve to the bundled sd-server as well as to a remote connection, so needing an image model does not mean needing a key or a network.
- [`tests/unit/worker/test_studio_job_router.py`](../../surfsense_local/backend/tests/unit/worker/test_studio_job_router.py) asserts that `job_router.py` names every catalog key and nothing else, that each key has a pipeline, and that each pipeline takes its models, the sources, the prompt and, for a format with options, the options.

## The builder rule, and where it is broken

The rule ([ADR 0010](../adr/0010-studio-builders-not-sandboxes.md)): the model writes structured content, and a committed builder for that format renders it. Nothing the model wrote executes on the user's machine, so a bad reply is malformed JSON rather than arbitrary code, and there is no sandbox, no Docker and no receipt to verify. That is what lets Studio fit an offline app with weak local models. [ADR 0028](../adr/0028-model-written-code-runs-with-approval.md) has since allowed model-written code to run on the user's machine without a sandbox, and [ADR 0039](../adr/0039-document-scripts-run-without-approval.md) runs a model-written document script without asking in a process of its own; the builder rule still describes the eight formats below.

Eight formats follow it:

- **summary**, labelled Markdown: the model's markdown is the body, titled by its first `# ` heading, and is kept as a `.md` file the panel offers to download. The prompt asks for the document the user's prompt describes, and a summary of the sources when there is none. One made before the file was kept has none until it is regenerated.
- **mindmap**: JSON nodes, at most 10 branches, become a markdown outline, an H1 over nested bullets, which Markmap draws on the client and which stays readable as text.
- **flashcards**: JSON cards, written under a schema ([`schema.py`](../../surfsense_local/backend/worker/studio/content/flashcards/schema.py)), at most 20, become a deck JSON file and a markdown body.
- **quiz**: JSON questions, written under a schema ([`schema.py`](../../surfsense_local/backend/worker/studio/content/quiz/schema.py)), at most 10, each kept only with exactly four options and an answer among them, become a quiz JSON file and a markdown body.
- **html**: two paths by the selected model, chosen by `writes_script()` as for [Word and PDF](#word-and-pdf) ([ADR 0066](../adr/0066-web-pages-are-html-the-model-writes-without-network.md)).
  - **Below the bar:** a JSON title and sections, at most 10, each paragraphs or, from the capable and frontier tiers, a list of `points`; those tiers also give a one-sentence `summary` under the title. The compact tier is asked for neither, since each field more is a chance for a small model's JSON to break. Every value is HTML-escaped into a fixed template, so the page cannot carry a script. The template carries a fixed stylesheet ([`page_style.py`](../../surfsense_local/backend/worker/studio/web/html/page_style.py)) in the agent's pages' paper palette and type, light only, and every tier's prompt says the page holds text only, so the model describes no diagram or interaction the template cannot show.
  - **At the bar:** the model writes the whole page in one reply, kept as the version's spec so [Refine](#refine) can rewrite it, ([`written/page.py`](../../surfsense_local/backend/worker/studio/web/html/written/page.py)). Its tier prompt carries the agent's design guide whole (`skills/surfsense-html/design.md`), the no-network contract and the user's focus. The page is taken by its own markers, from its doctype (else its `<html>` tag) to its last `</html>`, never by a code fence, since a page may hold fenced samples of its own; it is stored with the no-network `<meta>` after its doctype, and checked: a reply with no page, one cut off before `</html>`, or one over 300 KB with its `<meta>`, goes back to the model with the reason, three attempts in all, then fails the job with "The web page failed: …"; it never falls back to the template. The title is the page's `<title>`, else its first heading, else the prompt or the sources; the body is the page's readable text ([`page_text.py`](../../surfsense_local/backend/modules/artifacts/web_pages/page_text.py)).
  - The agent uses neither: it writes its own page ([agent](agent.md#web-pages-the-agent-makes)).
  - Tests: [`test_studio_written_page.py`](../../surfsense_local/backend/tests/unit/worker/test_studio_written_page.py) holds the split, the guide in the prompt, a page out of a code fence, a cut-off or oversized page sent back, and the third failure failing the job; [`test_refine_web_page.py`](../../surfsense_local/backend/tests/integration/artifacts/test_refine_web_page.py) holds a written page's spec, its Refine into the next version, a template page refused, and the guide counted against the window. The viewer's sandbox and policy are in [`html-viewer.test.tsx`](../../surfsense_local/frontend/src/features/studio/viewers/html-viewer.test.tsx).
- **podcast**: the model outlines the episode from the brief, then drafts it segment by segment. Every segment sends the same one-line system prompt and the sources, and its whole draft prompt after them, because llama-server reuses a prompt only up to its first changed token. Measured through the drafting code on Qwen3 1.7B with about 6,200 tokens of sources: with the draft prompt first, every segment re-read the sources; after them, segments 2 to 4 read about 230 tokens each. The draft prompt goes after them whole: split, with what the segments share left ahead of the sources, the same model wrote half the dialogue, in long lines. Each reply is capped at 12 tokens per word of the segment's target, and never under a planned 250-word segment's worth. Uncapped, Qwen3 1.7B looped on a 225-word segment until its 40,960-token window was full, and the JSON retry, which replays the failed reply, could not fit. The target is the outline's own guess: Qwen3 1.7B once gave a segment 20 words, wrote past them, and a 240-token cap ended both replies mid-JSON. The chosen audio model voices every line through audio.cpp's server, and the transcript is the body.
- **image**: the model writes a title and an image prompt, and the image model paints the prompt.
- **infographic**: the model writes a factual brief (a title, a summary and up to 8 sections of label, value and detail), and the image model paints a prompt built from it in a fixed sketchnote style.
- **comic**: options `{kind, pages}`, one of ten kinds ([`kinds.py`](../../surfsense_local/backend/modules/artifacts/comic/kinds.py)) and 1 to 12 pictures, checked when the job is created. The model plans a title, a style line, a character sheet and each page's panels and lines, asked for in [`schema.py`](../../surfsense_local/backend/worker/studio/media/visual/comic/schema.py)'s shape; the plan is cut to the count asked for, since each picture is billed or takes minutes, and one short of it is refused. A reply that is not a plan is asked for once more with the reply replayed ([`asking.py`](../../surfsense_local/backend/worker/studio/media/visual/comic/asking.py)), which costs no picture. A second reply with no JSON in it is the model declining, often over the sources themselves, so the job fails with the model's first line rather than a parse error. Page 1 is drawn alone, the rest with page 1 as their reference by [the model that takes a picture in](#which-model-takes-a-picture), side by side on a remote model and one at a time on this computer; with none, each is drawn from its words and the version keeps `drawn_from_words`. A remote model letters each page's lines in bubbles; when any page is drawn by a local model, the image model or the one drawing pages 2 on, no page carries words, its lettering being unmeasured, and every page's lines are set in a strip under it, as a picture book's and a storyboard's always are. The strip sets letters Helvetica lacks in the Word and PDF builder's fonts ([`pdf_fonts.py`](../../surfsense_local/backend/worker/studio/office/markdown/pdf_fonts.py)), and a word too wide for a line, as Chinese or Japanese is, is cut between letters. The pages are bound by [`comic_binding/`](../../surfsense_local/backend/worker/studio/media/visual/comic_binding/), which the agent's comics share; the body is every page's panels and lines. A failed comic is never retried by the worker, since every page would be drawn again. No page is kept on its own, so a Studio comic has no Edit: Regenerate draws it again.

Two formats break it. PPTX and XLSX go through `office/`: the tier prompt asks the model to "write one standalone Python script" for the format's library (python-pptx or xlsxwriter), with a `SKILL.md` of authoring guidance beside each format, to the runner's contract: start with a `# title:` comment and save the file at `OUTPUT_PATH`. [`office/pipeline.py`](../../surfsense_local/backend/worker/studio/office/pipeline.py) runs the reply through [the runner](#script-documents), in its own process, never with `exec()` in the worker's. A failing script goes back to the model with its error and the traceback's end, for up to three attempts; one longer than 48,000 characters ran on rather than broke on a line, so it is not shown back but asked for again, shorter, since replayed it overflowed the window ([`script_attempts.py`](../../surfsense_local/backend/worker/studio/office/script_attempts.py)). On a local model each draft stops at 16,384 tokens: a deck's script measured about 3,000, and a 1.7B that looped wrote 130,171 characters for 272 s first. Its failure reason does not start `Script error: `, as for [Word and PDF](#word-and-pdf). The title is the `# title:` comment, else the prompt, the sources or the format; the body is the file's own text, read as a script document's is. No spec is kept: a deck or workbook Studio drafts has no versions and no Refine.

## Word and PDF

Studio's Word and PDF buttons take one of two paths, chosen by [`office/document/strength.py`](../../surfsense_local/backend/worker/studio/office/document/strength.py)`::writes_script()`. The model's measured level decides ([model capabilities](model-capabilities.md)): `agent` and `agent_limited` write a script, `studio_only` writes Markdown. A model not measured keeps the provisional rule: one served from this computer counts as small and a remote one as strong. Local is the selection's `Fingerprint.local`: llama.cpp, or a connection whose host is loopback, such as Ollama or LM Studio. A server on another computer of the network, or one addressed as `0.0.0.0`, counts as remote, as it does for [egress](../../surfsense_local/backend/modules/egress/service.py).

- **A small model writes Markdown** in one call ([`markdown_path.py`](../../surfsense_local/backend/worker/studio/office/document/markdown_path.py)), and committed builders render it under ADR 0010's rule ([`office/markdown/`](../../surfsense_local/backend/worker/studio/office/markdown/)). markdown-it-py parses CommonMark with GFM tables and strikethrough; raw HTML stays text. The Word builder starts from python-docx's default template with its Heading, `List Bullet` and `List Number` (three levels; a deeper list takes the third level's style and counts on its own), `Table Grid`, `Quote` and `Caption` styles. The PDF builder uses ReportLab's sample stylesheet on A4 with 2 cm margins and escapes every character ReportLab's paragraph markup would read. A link keeps its target only for `http`, `https` and `mailto`.
  - **Figures:** an image whose target is `image:<source id>-<n>` places that source figure ([documents](documents.md#figures)) at its own size or the text width, with its alt text as the caption below. Any other target, or a figure the selected sources do not hold, becomes its caption in italics.
  - **Charts:** a fenced `chart` block holds `{type, title, labels, series: [{name, values}]}`, with `type` bar, line or pie, one number per label, and one series for a pie. matplotlib draws it through its object API, with no pyplot state. A block that does not parse becomes a note; one that parses but does not match becomes a table of its data with a note saying why.
  - The body is the Markdown itself, and the title its first `# ` line.
- **A strong model writes a script** ([`script_path.py`](../../surfsense_local/backend/worker/studio/office/document/script_path.py)) to the runner's contract: save at `OUTPUT_PATH`, open a figure at `IMAGES_DIR/<name>.png`, start with a `# title:` comment. It runs through [the runner](#script-documents), never `exec()`, with the selected sources' figures it names. A failing script goes back to the model with its error and the traceback's end, for up to three attempts. Its failure reason does not start `Script error: `, because Retry, which asks the model again, is the fix here. The title is the `# title:` comment, else the file's first heading.
- **Both prompts list the figures of the sources that reached the model (`grounded_document_ids`) with their captions**, each cut at 200 characters, so the model can place them ([`figure_list.py`](../../surfsense_local/backend/worker/studio/office/document/figure_list.py)). A source whose figures were never extracted, or a Word source whose figures pass has not run yet ([documents](documents.md#figures)), offers none this time, and asking queues its figures pass.
- **Either way the spec is kept**, as `{"kind": "markdown" | "python", "text", "format", "images"}` with the figures it places, and the draft becomes v1 of its own document under the same `version` keys as a script document, so the version switcher shows it. `artifact_metadata["recipe"]` says how the spec was made: `{"kind": "draft"}`, or `{"kind": "refine", "instruction", "base"}`. Regenerate repeats the recipe: a draft re-resolves its recorded `source_scope` ([Grounding](#grounding)) and drafts from it again, and a refine asks for the same rewrite again, which needs none of its sources; a script document has no recipe, so Regenerate runs its script as stored. A refine's Regenerate first runs [Refine](#refine)'s window check against the model selected now, and refuses with the same reason when the rewrite no longer fits.

### Refine

`POST /artifacts/{id}/refine` with `{instruction}` (1 to 2,000 characters) rewrites the spec of a Word document or PDF Studio made, or of a web page a model at the bar wrote, into its next version ([`studio_documents/`](../../surfsense_local/backend/modules/artifacts/studio_documents/)).

- It refuses an artifact keeping no spec (`not_refinable`), one still being made (`already_generating`), one whose last run failed or was stopped (`version_unfinished`; it keeps the spec it had, but the panel no longer shows that version as made), and a script document the agent wrote, which keeps no recipe and is edited in its chat (`agent_made`) ([07](../proposals/file-agent/07-create-and-edit-mvp.md), decision 8). Each is a `409` whose `detail` is `{message, code}`: the sentence saying so, and the code the interface translates. It also refuses a spec the selected model's window cannot rewrite in one call (`409` `rewrite_too_long`: a reason naming the model, the document's size and the window, with `model`, `spec_tokens`, `needed_tokens` and `window_tokens` raw beside it for the interface to format), and answers without a usable chat model with the `{message, code}` detail a refused create sends, `needs_chat`. The window is the one the agent's limits come from: what llama-server loaded a local model with, which may load it, or what the remote catalog records, else 32,768 tokens. The check prices text at 4 characters a token: the prompt's 1,500 tokens, the list of figures (for a web page, the whole design guide its prompt carries instead), the instruction, and the spec read once and written again a quarter longer ([`fits.py`](../../surfsense_local/backend/modules/artifacts/studio_documents/fits.py)).
- It creates the next version, `pending`, with the base's title, prompt, resolved `source_document_ids` and `grounded_document_ids`, whose figures the rewrite may place and the window check counts, and the refine recipe, and answers `202` with it. Its `spec_kind` is the base's while it waits.
- The job sends the whole spec, fenced, and the instruction in one call, gets the whole revised spec back, and renders it as a draft of that kind would. A web page's spec is the page as the model wrote it, `{"kind": "html", "text", "format": "html"}`, without the policy SurfSense stores ahead of it; its rewrite is checked as a written draft is, three attempts in one conversation ([`written/page.py`](../../surfsense_local/backend/worker/studio/web/html/written/page.py)). Nothing is patched or diffed. The rewritten spec is kept only when it renders: a failed refine keeps none, is not retried by Huey, and leaves every earlier version as it was.
- The agent's `surfsense_read_document` and `surfsense_render_document` refuse any version of a document Studio made, with "This document was made in Studio: refine it there, or make a new document." ([07](../proposals/file-agent/07-create-and-edit-mvp.md), decision 8).

Studio uses no Electron `printToPDF`, which only draws the agent's Word and PowerPoint previews and its sources' pages ([agent](agent.md#previews)), and there is no ffmpeg in `surfsense_local`. A PDF is ReportLab through the builder, a Studio script or a script document.

## Script documents

The agent makes a Word document, a PDF, a PowerPoint deck or an Excel workbook by writing a Python script that SurfSense runs and keeps ([agent](agent.md#documents-the-agent-makes)). Studio's own Word and PDF keep a spec too ([above](#word-and-pdf)), and a strong model's script runs through the same runner. Studio's own PowerPoint and Excel scripts run through it too, but keep no spec: they draft through `office/` as above.

**The spec and the versions.** [`script_documents/service.py`](../../surfsense_local/backend/modules/artifacts/script_documents/service.py)`::create_script_document()` refuses a title outside 1 to 200 characters, a script outside 1 to 200,000, a format other than `docx`, `pdf`, `pptx` or `xlsx`, an image name no source in the workspace has, a base artifact outside the workspace, made in Studio (it keeps a `recipe`), or not a script document of the same format, and a template that does not fit, each in a sentence the agent reads. A template (`template_source_id`) is a source of the workspace whose original file is a `.docx` for a Word document or a `.pptx` for a deck; PDF and Excel take none ([`template_source.py`](../../surfsense_local/backend/modules/artifacts/script_documents/template_source.py)). A next version whose call names none keeps its base's, checked again, and a base's template that has since gone is refused with what to do instead. The template is recorded among `source_document_ids`. It creates the `ARTIFACT` document, `pending` and titled as asked, and the `artifacts` row with that format and this `artifact_metadata`:

```json
{
  "spec": {"kind": "python", "text": "<the script>", "format": "docx", "images": ["12-1"], "template_source_id": 9},
  "version": {"root": 40, "number": 2, "parent": 40},
  "source_document_ids": [12],
  "prompt": null
}
```

Each version is its own artifact. v1 is its own root; a version made from another takes that one's root and the root's highest number plus one, and names it as its parent. Nothing is migrated: the keys live in `artifact_metadata`, and the `artifact_versions` table the [file agent proposal](../proposals/file-agent/03-editable-artifacts.md) designs replaces them later. The service commits, then enqueues `studio_job`. `ArtifactRead` and the detail carry `version` (`{root_id, number, parent_id}`) and `spec_kind`, both `null` for an artifact that keeps no spec.

**The job.** When the spec's kind is `python` and it keeps no Studio recipe, as every agent's document of the four formats, the job skips `job_router` and asks no model ([`script_document/pipeline.py`](../../surfsense_local/backend/worker/studio/script_document/pipeline.py)). It copies the PNG of each named source figure ([documents](documents.md#figures)) or analysis chart, which it finds in the version's thread's `outputs/analysis/` ([`script_images.py`](../../surfsense_local/backend/modules/artifacts/script_documents/script_images.py)), and the template's original when the spec names one, and runs the script through the runner with `OUTPUT_PATH` named `document.<format>`. A template whose source has gone fails the run with that reason. A file that does not open as its format fails the run ("the script wrote a file that is not a valid .docx"). The body is the file's text: a Word file's paragraphs and table rows in order, with headings marked, through python-docx; a deck's slides in order, each headed `## Slide <n>: <title>`, with its text, table rows, `[picture]` and `[chart: <title>]` markers and speaker notes, through python-pptx ([`deck_text.py`](../../surfsense_local/backend/worker/studio/script_document/deck_text.py)); a workbook's summary through openpyxl, read-only: its sheet and chart counts, each sheet's used range and first 10 rows of up to 8 columns, and up to 20 formulas as `Sheet!B5: =SUM(B2:B4)`, at most 6,000 characters ([`workbook_summary.py`](../../surfsense_local/backend/worker/studio/script_document/workbook_summary.py)); or a PDF's text layer through pypdfium2, under the process's one pdfium lock ([`shared/pdfium.py`](../../surfsense_local/backend/shared/pdfium.py)), since pdfium is not thread-safe and four jobs run at once. The stored file is named after the title, with the characters no system accepts dropped. Status, cancellation and persisting are shared with every other job.

**Recalculated workbooks.** A workbook with formulas goes through [`recalculation.py`](../../surfsense_local/backend/worker/studio/script_document/recalculation.py) after its run, because Studio's viewer and every preview show cached values, and xlsxwriter caches 0 and openpyxl none. With Office support on ([office pack](office-pack.md)), LibreOffice recalculates a copy within 45 seconds and [`cached_values.py`](../../surfsense_local/backend/worker/studio/script_document/cached_values.py) writes each formula's value into the workbook the script wrote, at the XML level: only `<v>` and `t` of formula cells, and of the other cells an array formula fills, change, and `calcPr` gets `fullCalcOnLoad="1"`, so the formulas stay and Excel recalculates on open. LibreOffice's own re-written workbook is never kept. A formula LibreOffice computed to an error, or gave no value, is left blank rather than keeping the script's stale 0. The summary's rows then show those values in the formula cells, the formulas still listed below. The version's metadata records `recalculation: {by, formulas, left_blank, reason}`: `by` names LibreOffice and its version, or is null with the reason the values were not recalculated ("Office support is off.", LibreOffice busy or out of time, or a failure, which never fails the version); a workbook without formulas records null. Without Office support the file is delivered as the script wrote it. The render result reads the record ([agent](agent.md#documents-the-agent-makes)).

**No retry.** A failed script document, the agent's and so without a `recipe`, is never retried by Huey, whatever failed: running the same script fails the same way, and its agent reads the failure and renders the fix as the next version, which a retry turning the old one ready would race. Its reason is `Script error: `, the error and as many of the traceback's last lines as fit in 500 characters; a failure outside the script, such as the embedder, keeps its own reason without that start, so the agent renders the same script again instead of rewriting it ([agent](agent.md#documents-the-agent-makes)). Regenerate on a ready one runs the same script again.

**The runner** ([`document_script/run.py`](../../surfsense_local/backend/worker/document_script/run.py)) runs one script in its own process, because only a process can be stopped at its limit ([ADR 0039](../adr/0039-document-scripts-run-without-approval.md)). The agent's analyses run through it too ([below](#analysis-runs)):

- **The folder.** A fresh `<data>/tmp/document-scripts/<uuid>/` holds `script.py`, `images/<name>.png` and, for a template, a copy of the source's file as `template.docx` or `template.pptx`, so nothing the script does reaches the source; it is removed afterwards. A worker killed mid-run leaves its folder, so the Studio worker removes every one when it starts, before it takes a job. The script SurfSense stored is the spec, so a script that rewrites its own file changes nothing kept.
- **The process.** The worker in its `--run-document-script <folder>` mode, which loads no queue, database or settings: the frozen backend binary when packaged, `worker.py` on the backend's Python in development. The child changes into the folder and runs `script.py` as `__main__`; a failure prints the traceback without the runner's own frames and exits 1.
- **Its environment** is built, not inherited: `PATH`, plus `SYSTEMROOT`, `WINDIR`, `TEMP` and `TMP` on Windows or `HOME` and `LANG` elsewhere, then `OUTPUT_PATH`, `IMAGES_DIR`, `TEMPLATE_PATH` only when the run has a template, `MPLBACKEND=Agg`, `MPLCONFIGDIR` inside the folder, `PYTHONUTF8=1`, `PYTHONDONTWRITEBYTECODE=1` and `OPENBLAS_NUM_THREADS=1`, since numpy's OpenBLAS otherwise commits a buffer per CPU thread as it loads, about 0.5 GB on 16 threads. No key, secret or `OPENCODE_*` variable reaches it.
- **The limit** is 120 seconds, and a cancelled job stops its script within a second. A cancel check that finds the database locked past SQLite's busy wait skips that look rather than fail a script with nothing wrong. Either way the script and everything it started are killed: on Windows a job object holds them from the start and dies with the worker too; elsewhere the script leads its own process group, which it kills when the worker's end of its stdin closes.
- **The result** is the file's bytes, or one line the agent can act on ("SyntaxError: …", "timed out after 120 s", "the script wrote no file at OUTPUT_PATH") and the last 30 lines of the traceback. The worker keeps only the last 64 KiB of the script's stderr, which a runaway script could fill with gigabytes. Paths in the run folder are written relative to it, anywhere in that stderr: a warning's, a frame's, or one in an exception message, which on Windows has its backslashes doubled. Its stdout is drained too, so a script that prints a lot never blocks; a document script's is dropped.

**Analysis runs.** `surfsense_analyze_data` ([agent](agent.md#analyses)) queues `analyse_data` on the Studio queue at priority 100, ahead of Studio's own jobs, dropped if not started within 60 seconds, and waits for its Huey result ([`data_analysis/task.py`](../../surfsense_local/backend/modules/agent/data_analysis/task.py)). It runs in the Studio worker because the packaged worker is the binary that ships pandas. [`analysis_run.py`](../../surfsense_local/backend/worker/document_script/analysis_run.py) gives the script a run folder with `input/`, holding a read-only copy of each source's original file under its own name (a second file of the same name gains ` [<id>]`) and `manifest.json`, which lists each copy's `file`, `document_id` and `title`, and an empty `output/`; the environment has `INPUT_DIR` and `OUTPUT_DIR` in place of `OUTPUT_PATH` and `IMAGES_DIR`, the rest as above. It keeps the first 64 KiB of stdout and counts the rest. On success the files at the top of `output/` move into the thread's `outputs/analysis/<run>/` ([`kept_outputs.py`](../../surfsense_local/backend/worker/document_script/kept_outputs.py)): only `.csv`, `.tsv`, `.png`, `.jpg`, `.jpeg`, `.svg`, `.xlsx`, `.json` and `.txt`, never Markdown, which opencode could read as instructions, at most 20, each at most 25 MB, named with letters, digits, `_` and `-` and at most 40 characters before the suffix. Anything else is named as not kept. A failed run keeps nothing. The folder goes afterwards, its read-only copies made writable first.

The libraries a script may use are the worker's: python-docx, ReportLab, python-pptx, xlsxwriter, openpyxl, matplotlib, Pillow, numpy and pandas ([packaging](packaging.md)). openpyxl and pandas, which Docling also brings, are named in `pyproject.toml` and frozen by name in `bundling/worker_inputs.py`.

## Converted PDFs

`surfsense_convert_document` ([agent](agent.md#converting-to-pdf)) makes a PDF artifact whose metadata holds `conversion: {artifact_id, document_id}`, `version` as v1 of its own document, and, for a source, `source_document_ids` naming it ([`converted_documents/`](../../surfsense_local/backend/modules/artifacts/converted_documents/)). The job takes it before any other path: it finds the file again, a ready Word or PowerPoint version's own file or a source's `.docx` or `.pptx` original, and fails in a sentence when either is gone; commits; then LibreOffice converts a copy within 120 seconds ([`converted_document/pipeline.py`](../../surfsense_local/backend/worker/studio/converted_document/pipeline.py)). The body is the PDF's text layer, as a script PDF's is. With Office support turned off since, the job fails with "Office support is off, so nothing can convert this file to PDF." A failed conversion is not retried by Huey, since the tool waits on it; Retry and Regenerate convert the same file again. `renders_as_stored()` counts a conversion, so Regenerate needs no chat model and re-resolves no sources: a PDF of an artifact has none. The PDF keeps no script, so it cannot be continued with `artifact_id`; the agent changes the Word version or deck and converts again.

**In Studio.** The list shows each document once, as its newest version with a "v3" badge, and opens the newest version that finished while the next one is still being made ([`artifact-versions.ts`](../../surfsense_local/frontend/src/features/studio/artifact-versions.ts)). When the newest version failed and an earlier one is ready, the row stands for that ready version, with a muted mark whose tooltip names the failed one ([`artifact-list.tsx`](../../surfsense_local/frontend/src/features/studio/artifact-list.tsx)). The viewer has a version switcher, and a newer version of the open document opens itself when it appears. A version its script failed, whose reason starts `Script error: `, offers no Retry and no toast, and its alert's tooltip says to ask the agent; one that failed for any other reason, such as the app closing mid-run, offers Retry, from the row's menu as "Retry v4" when an earlier version is ready ([`can-retry.ts`](../../surfsense_local/frontend/src/features/studio/can-retry.ts)). Deleting the document deletes every version, after a dialog that counts them, and is refused while one is being made. None of this depends on the format: a deck or workbook the agent made lists, switches and retries as a Word document does, in the Slides and Spreadsheet viewers. An artifact without a version looks as it always has.

## Revised copies

The agent edits the user's own `.docx`, `.xlsx`, `.xlsm` or `.pptx` source through `surfsense_revise_document` ([agent](agent.md#revised-copies-the-agent-makes)). The result is a new artifact derived from the source, never the source itself (the [file agent proposal](../proposals/file-agent/03-editable-artifacts.md), decisions 11 and 12), and each later edit is its next version.

**The versions.** [`revised_copies/service.py`](../../surfsense_local/backend/modules/artifacts/revised_copies/service.py) makes each one as a script document's is: an `ARTIFACT` document, `pending`, and an `artifacts` row in the format the suffix picks (`docx`, `xlsx` for `.xlsx` and `.xlsm`, `pptx`), with `version` and `source_document_ids` as [above](#script-documents), `spec: null`, and a `revision` record ([`revision.py`](../../surfsense_local/backend/modules/artifacts/revised_copies/revision.py)):

```json
"revision": {
  "derived_from_document_id": 42,
  "source_name": "MSA_Acme.docx",
  "source_sha256": "…",
  "base_number": 1,
  "action": "edit",
  "operations": [{"op": "replace_text", "quote": "within 30 days", "text": "within 45 days"}],
  "report": {"schema": "revise-report/1", "saved": true, "ops": [], "applied": 1, "refused": 0, "skipped": 0, "must_tell_user": [], "input_sha256": "…", "output_sha256": "…"},
  "counts": {"changes": 2, "comments": 0},
  "internal_comment_ids": [],
  "clean": {"storage_key": "…/clean.docx", "size_bytes": 1, "checksum_sha256": "…"},
  "external": null
}
```

v1 is titled `<source stem> (revised)` and starts from the source's original file; `source_sha256` is the file as the tool checked the edits against it, and `base_number` is null. A next version starts from the newest ready version, whichever version was named, and is refused while any version of the copy is still being made ([`versions.py`](../../surfsense_local/backend/modules/artifacts/revised_copies/versions.py)). `action` is `edit`, or `accept_all` and `reject_all` for the panel's buttons.

**The engines** ([`revised_copies/engines/`](../../surfsense_local/backend/modules/artifacts/revised_copies/engines/)) are pure functions over files, written from ECMA-376: no database, no model and no Office. Each parses the package with lxml with entity resolution, DTD loading and network access off, refuses a part with a DOCTYPE or a damaged compressed stream, and caps every part at 64 MiB decompressed, the package at 512 MiB and 10,000 entries. Operations apply in order and all or nothing: one refused operation skips the rest and saves nothing, and a run that changes nothing saves nothing. Each returns a report of every operation as `{code, values}` with an English sentence. Word writes every change as a tracked change by "SurfSense", a comment where asked, and accepts, rejects, counts and strips internal comments; Excel writes cell values and formulas into the sheet XML alone (a formula whose brackets or quotes do not pair up is refused, since Excel would drop it in a repair), leaving charts, drawings and every other part byte for byte, and marks the workbook to recalculate on open. It holds the requester's own rules as Excel does when typing: a locked cell of a protected sheet is refused (`CELL_LOCKED`), and a value off the cell's list dropdown, compared exactly, is refused naming what the list allows (`VALUE_NOT_IN_LIST`), unless the rule shows no error alert or its error style only warns; clearing a cell and writing a formula pass. Lists are read from a literal, a range on any sheet, a defined name, and Excel 2010's `x14` form in the sheet's `extLst`, which openpyxl drops, and a list cell holding a formula is read by its last result, as the dropdown shows it ([`excel_dropdowns.py`](../../surfsense_local/backend/modules/artifacts/revised_copies/engines/excel_dropdowns.py), [`excel_protection.py`](../../surfsense_local/backend/modules/artifacts/revised_copies/engines/excel_protection.py), [`excel_inspection.py`](../../surfsense_local/backend/modules/artifacts/revised_copies/engines/excel_inspection.py)). `add_sheet` appends a sheet of values after the others, its header row frozen, under a name Excel accepts and no sheet holds, so a job's sources and exceptions travel in the file without moving what the requester imports ([`excel_new_sheet.py`](../../surfsense_local/backend/modules/artifacts/revised_copies/engines/excel_new_sheet.py)); PowerPoint replaces text in place and deletes or duplicates slides. Quotes are matched against the text as it reads now, within one paragraph, and must match once.

**The job.** `_generate` takes a version with a `revision` before any other path but a [conversion](#converted-pdfs) ([`revised_copy/pipeline.py`](../../surfsense_local/backend/worker/studio/revised_copy/pipeline.py)): it finds the input in a short read, commits, and copies the input into a scratch folder, so nothing is written beside the user's file. v1 fails with "The source file changed on disk after the edits were checked. Ask again…" when the copy's SHA-256 is not `source_sha256`, and when the source's file is gone. The engine runs on the copy with no transaction open; a report that saved nothing fails the version with its first refused operation. A Word version then gets its counts (`w:ins`, `w:del`, `w:moveFrom` and `w:moveTo` in the body, and comments), `external` when any of its comments is internal (those comments removed), and `clean`, every change accepted and no comments; its indexed body is the clean file's text, so search finds the wording as it now reads. A workbook's body is its summary and a deck's its slide text, as a script document's. After persist, `clean.docx` and `external.docx` are written beside the primary in the artifact's folder and recorded in `revision`, with the report and counts ([`record.py`](../../surfsense_local/backend/worker/studio/revised_copy/record.py)). A failed revised copy is never retried by Huey: the same edits on the same file fail the same way. Regenerate and Retry apply the stored edits to the same input again and ask no model. A [job run](jobs.md#runs) is the one revised copy whose edits a model works out: its v1 arrives with no operations and a `job_run` record, and the job's runner fills them in, on the selected model, before the engine applies them.

**Downloads.** "With changes" serves `external` when the version has internal comments, and nothing when that file is gone, never the primary that holds them; else the primary; "Clean" serves `clean`, Word only. Each is named `<source stem> (<suffix> v<n>).<ext>`, the suffix being the interface's translated "revised" or "clean", English when none is passed, with the characters no file system takes dropped, a `_` before a Windows device name, and at most 255 bytes ([`downloads.py`](../../surfsense_local/backend/modules/artifacts/revised_copies/downloads.py)).

**In Studio.** The artifact panel shows "Revised copy of MSA_Acme.docx" and "7 tracked changes, 2 comments", or for a workbook or deck "4 changes in this version"; Accept all and Reject all for a Word copy with changes, on its newest ready version only (a decision starts from that one), disabled while a version is being made, which post the route and open the new version once ready; and the two downloads in place of the file's own, on a ready version only: a version being made, failed or cancelled has no file of its own ([`revised-copy-bar.tsx`](../../surfsense_local/frontend/src/features/studio/revised-copy-bar.tsx), [`revised-copy-downloads.tsx`](../../surfsense_local/frontend/src/features/studio/revised-copy-downloads.tsx)). A workbook copy, one whose source is a `.xlsx` or `.xlsm`, also reads its [job run](jobs.md#runs) by its root, again on each `artifacts` event, and a copy that is not a run answers `404` and shows nothing more; on a run's newest ready version, while no version of it is being made and suggestions are open, the bar adds Confirm N suggested answers, the Jobs screen's own button: it lists every open suggestion in a dialog, its question, suggested answer and cell, then posts the run's confirm route, and a toast says a new version is being written. The Word viewer and the agent's page previews draw tracked changes, insertions underlined and deletions struck through.

## Files a tool made

The agent's PDF tools make their file themselves ([agent](agent.md#pdfs-the-agent-works-on)), as the agent writes its web pages ([agent](agent.md#web-pages-the-agent-makes)), so [`made_file.py`](../../surfsense_local/backend/modules/artifacts/made_file.py)`::keep_made_file()` stores it before any job runs: it refuses a title outside 1 to 200 characters and a workspace with no embedding model chosen, creates the `pending` `ARTIFACT` document and the `artifacts` row with its `chat_thread_id`, writes the bytes to the artifact's folder as `primary.<format>` with their `artifact_files` row, named after the title, commits, and enqueues `studio_job`. Its `artifact_metadata`:

```json
{
  "made_by": {"tool": "pdf_pages", "operation": "extract", "pages": "1-3"},
  "derived_from": {"document_ids": [12], "artifact_ids": [40]},
  "source_document_ids": [12],
  "prompt": null
}
```

A PDF tool's file keeps no `spec` and no `version`, so it lists as a document of its own and no render continues it. A saved page is the exception: `add_made_file()` stores it without committing, and [`saved_page.py`](../../surfsense_local/backend/modules/artifacts/web_pages/saved_page.py) adds the `version` keys a script document has before the commit, so its versions list together; `made_by` is `{"tool": "save_page", "path": "outputs/<name>.html"}`. `renders_as_stored()` counts it, so the job asks no model and Regenerate needs none: the job reads the kept file's text as a script document's is read, for a PDF, Word file, deck or workbook, or a page's readable text as Markdown ([`page_text.py`](../../surfsense_local/backend/modules/artifacts/web_pages/page_text.py)), and persists the same bytes ([`made_file/pipeline.py`](../../surfsense_local/backend/worker/studio/made_file/pipeline.py)). A kept file that is missing or does not open fails the job, never retried, with "The kept file does not open as a PDF."

## Voicing a podcast

[`providers/audiocpp/`](../../surfsense_local/backend/modules/llm/providers/audiocpp/) voices a podcast with the `audio_gen` model, an audio.cpp build installed in the audio folder ([`local-models/catalog.md`](local-models/catalog.md)):

- **The voices are the model's roster**, from its manifest entry: each voice with the languages it speaks, one for a Kokoro or Kitten voice and all 31 for a Supertonic voice. The brief's language list, A to Z by the name shown in the interface language, and each speaker's voice picker come from it, the picker grouped into female and male voices. The brief opens in American English where a voice speaks it, else in any English, else in the roster's first language, and a remembered brief the chosen model cannot voice falls back to that.
- **Memory is checked before anything loads, twice.** The worker compares the operating system's available memory (`MemAvailable` on Linux, free plus inactive pages on macOS, `GlobalMemoryStatusEx` on Windows) with the model's peak measured while voicing with every chunk of text full, from its entry, plus 1 GiB, and refuses short of it: "Voicing needs about 3.5 GB free; this computer has 1.8 GB. Supertonic 3 needs about 1.6 GB." The second sentence names the first other curated audio model, in the manifest's order, that would fit, and is left out when none would. It checks first, before the chat model drafts anything, so a machine that cannot voice the episode does not spend minutes writing it. Short there, it gives up the text runtime through the API ([the image job's hold](local-models/admission.md#the-image-jobs-hold)), which lets running replies finish and unloads the chat model, checks again, and lets it go for drafting, because voicing frees that memory anyway: on 16 GB, Qwen3 1.7B resident left 3.3 GB free and refused Kokoro's 3.5 before a word was drafted. At voicing it gives the runtime up again and holds it until the last turn is voiced, so a chat sent meanwhile waits instead of loading the chat model back into memory voicing needs. The hold also unloads the speech recognition model and starts no recording's window until it ends, while dictation goes on behind its own memory check ([admission](local-models/admission.md#speech-recognition)). The router reloads the chat model on the next request after either. Each check waits up to 10 seconds for memory the app is giving back before it refuses, because a starting podcast ends sd-server's idle minutes but Electron stops it only on its next 5-second poll ([the image path](#the-image-path)). audio.cpp's own guard counts only the file it reads.
- **One speech request per turn**, with the turn's voice. The brief's language goes in the request only for a voice that speaks several; a Kokoro voice's name already fixes its language. The turns are joined with 0.35 s between them.
- **The episode is MP3**: the joined 16-bit WAV is encoded in-process by LAME through `lameenc`, at 64 kbit/s per channel and the model's own channels and rate, about a sixth of the WAV ([`encoded_episode.py`](../../surfsense_local/backend/modules/llm/providers/episode_audio/encoded_episode.py)). The podcast pipeline encodes whatever WAV a voice returns, local or a server's, so a voice's `synthesize` stays WAV for every other caller, such as Settings' voice check, which plays it as it came. No ffmpeg and nothing on the user's `PATH` is used. Where `lameenc` cannot be imported, as in a checkout that skipped it, or its encode fails, the episode stays WAV, which the viewer's `<audio>` plays the same: the voices are paid for by then, so the episode is kept rather than failed and voiced again.
- **A turn the server fails ends the episode with the server's own words**: "audio.cpp could not voice turn 3 of 40: unknown Kokoro voice id: nobody". The server was reached, so this is not "The model could not be reached", which stays for a server that does not answer.
- **The model is unloaded when voicing ends**, with `POST /v1/tasks/unload_all_models`, success or failure, so its memory is back before the chat model's next job. The server's five-minute idle unload is the backstop.

### On a server

[`providers/openai_compatible/speech.py`](../../surfsense_local/backend/modules/llm/providers/openai_compatible/speech.py) voices a podcast with an `audio_gen` model chosen from a connection:

- **The voices are the server's, or the user's, never guessed.** The OpenAI API has no route that lists voices and models.dev carries none, so the server is asked `GET {base}/audio/voices`, Kokoro-FastAPI's route ([`voice_list.py`](../../surfsense_local/backend/modules/llm/providers/openai_compatible/voice_list.py)), held for the process and never stored. A server without it may publish them per model: OpenRouter's model list carries `supported_voices` on most of its speech models ([`published_voices.py`](../../surfsense_local/backend/modules/llm/providers/openai_compatible/published_voices.py)), read from `GET {base}/models?output_modalities=all`, held the same way. That list also voices ids it leaves out, such as an ElevenLabs voice's raw id, so it is a suggestion: the roster's source is `published`, and the user can add more. A model with neither, as on OpenAI and Groq, takes only the voices the user adds in Settings › Audio generation models, inside that server's section under its model in use, and in onboarding's server path alike: each is voiced once before it is kept, under `voices` in the selection's `settings`, which is cleared when the slot takes another model. For OpenRouter alone, a model publishing no list has the section link its page, whose "Request fields" name its voices; no other provider publishes them at an address the app can build. It opens in the OS browser, which the app allows for OpenRouter pages of that shape only ([`egress.md`](egress.md)). One slice, [`llm/voices/`](../../surfsense_local/backend/modules/llm/voices/), answers which voices the chosen audio model offers, local or server, for the brief and Settings alike. The server is asked only once its host is allowed, and only after the request's transaction has ended, so a slow server never holds the database; the format list never asks.
- **Nothing says which languages a server's voice speaks**: not the API, not `/audio/voices`, not models.dev. So a voice is heard, in Settings and in the Try dialog, saying a line in the interface's language, the one the user likeliest writes in, and the brief offers a fixed list of script languages. A voice that cannot speak the chosen language reads it anyway, badly: no server reports it as an error.
- **The brief reads like the local one.** It adds one line, "Voiced by {model} on {server}. Each line is billed by the provider.", and otherwise keeps the local labels; only its lists differ, the voices one plain list with no gender the server did not state. With no voices yet, the brief shows only a Set up voices button, which opens Settings, and Generate is held. The brief response carries `voices_source` (`local`, `server`, `published` or `saved`) and `voiced_by`.
- **No voice is checked before drafting.** A listed or published voice came from the server and an added one was heard when it was added, so the brief's own check, that each speaker's voice is one of them, is what stands between the user and a voice the server refuses.
- **Only OpenAI's `/audio/speech` is spoken, and ElevenLabs' own.** Gemini and other providers with their own speech APIs are reached through a gateway that speaks it for them, OpenRouter or a LiteLLM proxy, rather than through an adapter per provider here. ElevenLabs is also reachable that way, and has [a connection of its own](connections.md#elevenlabs) for the user's own account and voices ([ADR 0084](../adr/0084-elevenlabs-is-a-connection-with-its-own-client.md)). Its client sends one `POST /v1/text-to-speech/{voice_id}` per line as `wav_24000`, with `language_code` when the brief has one, since a language the model does not speak otherwise reads badly with no error. It leaves out blank lines, which would bill nothing and voice silence. At most two requests per account are in flight from a process ([`request_slots.py`](../../surfsense_local/backend/modules/llm/providers/elevenlabs/request_slots.py)), the Free plan's limit on v4, since Studio runs four jobs. A 429 from another process or client of the key is repeated after 1, 2, 4 and 8 seconds, because that is refused at once and billed nothing. Its voices state a name and gender, and its model's languages, so what follows on naming none does not apply to it.
- **One `POST /audio/speech` per turn**, asking for `wav`, because only WAV takes a pause between speakers. When the first line's `wav` is refused, the episode asks for `pcm`, then for `mp3` if that is refused too or is raw audio whose `Content-Type` states no rate, the one case that voices the first line twice: OpenRouter takes only `mp3` or `pcm`, and answers `audio/pcm;rate=24000;channels=1` ([`pcm_reply.py`](../../surfsense_local/backend/modules/llm/providers/openai_compatible/pcm_reply.py)). `pcm` becomes a 16-bit WAV at the stated rate, so a pause joins it; a rate is never guessed, since a wrong one changes the voice's pitch, and a later line that states none ends the episode. An answer to `pcm` that is already WAV or MP3 is kept, since asking again would bill the line twice. A first line every format refuses reports the last refusal, because OpenRouter refuses `wav` before it reads the key or the voice. The format is read from the bytes, not from what was asked. WAV turns join as audio.cpp's do, and a reply holding several WAVs back to back is one turn. MP3 turns join frame to frame without a pause, each turn's ID3 tag and Xing frame dropped so a player reads the whole episode's length. Anything else ends the episode with "the server answered, but not as WAV or MP3". A WAV episode is then encoded as MP3 as audio.cpp's is; an MP3 one is kept as the server sent it.
- **Nothing is checked for memory**, since the server spends it.
- **A failure is not retried.** A refused turn, an unreachable server or an unreadable answer ends the episode with the server's own words, and the job is not retried, because a retry would draft and bill the whole episode again.

## Grounding

[`shared/gather.py`](../../surfsense_local/backend/worker/studio/shared/gather.py) loads the selected documents' markdown, and [`shared/generate.py`](../../surfsense_local/backend/worker/studio/shared/generate.py) sends it as one user message, each document under its title as a heading, after the format's system prompt. A format that calls the model several times over the same sources puts what differs per call after them, in the same message (`after_sources`). The budget is what the text model's window leaves for the sources, at most 24,000 characters ([below](#the-window-budget)).

- A selection that fits is sent whole, in selection order, and nothing is searched.
- A larger one gives every document an even share of the budget. A document shorter than its share is sent whole, and what it leaves goes to the others, so no selected document is left out.
- With a prompt, each share holds that document's passages that best match it, found by one `retrieve()` call scoped to the selection ([`search.md`](search.md)). They are kept in reading order, with `[...]` where text between them was skipped. A document with no match, and every document when there is no prompt, contributes its start.
- When the even share would fall below 1,500 characters (`MIN_SHARE_CHARS`, about one chunk), cutting every document to a sliver says nothing, so one `retrieve()` over the selection takes its best passages for the prompt, else the format's `default_focus`, up to the budget. Only documents holding a chosen passage are sent.
- The job records `grounded_document_ids` in `artifact_metadata`: what reached the model, so the panel can say "Grounded on 14 of 212 sources".
- Markdown and mind map read a document's shape, Markdown because with no prompt it summarises, so they always take each document from its start (`Grounding.WHOLE` on the format in [`formats.py`](../../surfsense_local/backend/modules/artifacts/formats.py)). The other formats take passages.
- The search embeds the prompt, which loads the embedding model in the Studio worker, as persisting an artifact already does.

### The window budget

Every format sizes its sources the same way, in `_draft` before the pipeline runs ([`shared/window_budget.py`](../../surfsense_local/backend/worker/studio/shared/window_budget.py)), since a local model may be loaded with as little as 8,192 tokens ([#2421](https://github.com/MODSetter/SurfSense/issues/2421): an infographic's 24,000 characters of sources made an 8,545-token request, which llama-server refused).

- **The window** is read through the API's model route for the model the job started with ([admission](local-models/admission.md#the-model-route)): what llama-server loaded a local model with, which may load it, or what a remote model's plan or the remote catalog states. Under an image's or a podcast's hold, a local model's is the window admission last read, so nothing loads under the hold. A window nothing states, or one that cannot be read, leaves the 24,000-character ceiling, as before.
- **The room** for the sources is the window less 1,200 tokens for the longest system prompt a draft sends but a written web page's (a deck's script prompt at the frontier tier, 3,410 characters), the user's prompt, 8 tokens a message for four messages, a quarter of the window for the reply, and a tenth as a margin. At the 8,192 floor that leaves 4,092 tokens, about 12,000 characters of English. Less room than about one chunk (500 tokens) fails the job at once: "The model's context window, 2,048 tokens, is too small to hold any of the sources. Choose a model with a larger context window."
- **The fit.** The first budget is three characters a token. What gather returns is priced as admission prices a prompt, three Latin characters or one other character a token, with each document's title and, for Word and PDF, the list of figures the draft may place ([`cost.py`](../../surfsense_local/backend/modules/llm/admission/cost.py)). Past the room it is gathered again with the text cut at its own density, which is how Chinese, at about a token a character, gets a third of the characters; after three gathers still past it, the job fails with "The selected sources don't fit the model's context window. Select fewer sources, or choose a model with a larger context window."
- **Trimmed, not summarised.** The cut is gather's own: even shares, else the best passages, with `[...]` where text was skipped, every document under its title, and `grounded_document_ids` naming what reached the model. Summarising would ask the model once more per source on the small machines the budget is for, each call bounded by the same window.

Each format keeps its prompts as markdown beside its code, one file per model tier, loaded for the selected model's tier ([`local-models/selection.md`](local-models/selection.md)). The user's prompt joins the system prompt as a "Focus on:" line.

Every pipeline returns a `Built`: a `title`, the `markdown` that is always the indexed body, and an optional `primary` (and `preview`) with its MIME type and filename. Frontend entries below customize its translated label, icon, tooltip and viewer; an unknown key still appears with the server's label, a file icon, the generic tooltip and the document viewer.

## Jobs

- `studio_job` runs on the `studio` Huey queue in `huey.db` with `retries=1`. Every path that makes a version commits its row and then queues its job through one helper ([`queued_job.py`](../../surfsense_local/backend/modules/artifacts/queued_job.py)), since the worker is another process that must find the row. A job that cannot be queued fails its version with "This could not be queued. Retry it." rather than leaving it `pending` with no job to end it, which would refuse every Retry and edit. `worker-studio` drains it with four threads, because the work mostly waits on a model ([ADR 0008](../adr/0008-two-job-queues.md)).
- A job ([`job.py`](../../surfsense_local/backend/worker/studio/job.py)) marks the document `processing` unless it was cancelled, resolves one model per required model type, commits, asks the API for the text model's window, gathers the sources to it, and commits again before rendering, so no write lock is held across a generation that can take minutes. The first commit is because the API needs the write lock to answer: held, every window lookup waited out the busy timeout, failed as `database is locked`, and failed the API's other requests with it. It checks for a cancel before and after rendering.
- [`persist.py`](../../surfsense_local/backend/worker/studio/shared/persist.py) chunks and embeds the body with the ingest code, with no transaction open, then sets the document's title and markdown and indexes that body, so the artifact is searchable and citable. If the format has a file, it clears the artifact's folder and file rows and writes the file named by its role, recording its size and SHA-256. No pipeline writes a `preview` yet.
- The document is created without a `dedup_key`, so it is never deduplicated against another document.
- A failure rolls back and writes `failed` with a reason cut to 500 characters: the error's first line, or for an HTTP error its whole message after "The model could not be reached: ". A model that refused a request past its window was reached, so that refusal (llama-server's `exceed_context_size_error`, or the `context_length_exceeded` OpenAI and servers copying it send) reads, for a draft, as the [window budget](#the-window-budget)'s "don't fit" sentence, and for a refine or a job run, "The request was longer than the model's context window. Choose a model with a larger context window." The job is then re-raised for Huey's one retry, except an image error, since the endpoint may already have generated, and billed, an image, a podcast refused for memory, since a retry would draft the episode again and refuse again, a request past the model's window or sources it cannot hold, since the same request is refused the same way, any failure of a script document ([above](#script-documents)) of a converted PDF ([above](#converted-pdfs)) or of a revised copy ([above](#revised-copies)), and any failure of a refine ([Refine](#refine)) or an image edit ([editing a picture](#editing-a-picture)), which Retry asks again.
- **Cancel** marks the document `cancelled` and revokes a queued copy. A running job stops at its next check. During a model call it checks every second, while tokens stream, while the request waits for admission and while the model is still reading the prompt, and hangs up; closing the request leaves the line, or closes the API's stream to the model, which stops llama-server within 1.5 seconds, measured through the router ([`generate.py`](../../surfsense_local/backend/worker/studio/shared/generate.py)). A podcast checks before voicing each turn, so the rest of the episode is never sent, and an office job checks before each attempt, so a cancelled job asks the model for no retry. The check is a context variable ([`shared/cancellation.py`](../../surfsense_local/backend/shared/cancellation.py)), in `shared/` because the audio.cpp provider reads it too.
- Every Studio model call turns thinking off. Measured on Qwen3 1.7B: with it on, a mindmap over a 12,000-token prompt thought past 15,000 tokens without answering, holding a runtime slot all the while.
- Every text call goes through the API's model route, for every model, local or remote: the API resolves the model the job started with, checks egress, and on the local runtime admits it as background work, behind chat ([admission](local-models/admission.md#the-model-route)). Errors reach the job as the types a direct call raises, so its retries and its one-line reason are unchanged; a refusal past the window is `ContextOverflowError`, an `httpx.HTTPStatusError` with status 400, told apart in the API while the provider's body is still readable ([`context_overflow.py`](../../surfsense_local/backend/modules/llm/providers/context_overflow.py)). The job's panel stays `processing` while it waits.
- **A job the app quit in the middle of** is failed with `interrupted when the app closed` when the Studio worker next starts, before it takes a job ([`interrupted_documents.py`](../../surfsense_local/backend/worker/interrupted_documents.py)): Huey dropped the job as it started it, so nothing else would end it, and Regenerate would refuse it forever.
- **Regenerate** refuses a job still `pending` or `processing`, rechecks availability (not for a script document, a made file or a converted PDF), resets the document to `pending`, clears the error, increments `generation` and re-enqueues with the same sources, prompt and options. The new run replaces the files and the indexed body; the artifact and its document keep their ids.
- Each transition the Studio worker makes sends an `artifacts` event keyed by artifact id; the API's own changes, to `pending` and `cancelled`, send none. The artifact list reloads on each event, and so does an open artifact, and the list still refetches every 10 seconds while a job is running, in case a notice was lost ([`overview.md`](overview.md#freshness)).

## Routes

| Method | Path | Does |
|---|---|---|
| `GET` | `/workspaces/{workspace_id}/studio/formats` | the catalog, each format with `available`, `unavailable_reason` and `unavailable_code`, the same reason as a code the interface translates |
| `POST` | `/workspaces/{workspace_id}/studio/jobs` | `{format, source_scope?, document_ids?, prompt?, options?}`; a `source_scope` is resolved on the server and recorded in `artifact_metadata` beside the resolved `source_document_ids`, and wins over `document_ids`; nothing ready is `422` with the code `no_sources`, or `409` `sources_indexing` while the scope's sources are still indexing; `201` with the artifact |
| `GET` | `/workspaces/{workspace_id}/studio/podcast/brief` | the podcast brief to review before submitting, the model's `voices` (`null` when they are typed) and the `languages` it may use |
| `GET` | `/workspaces/{workspace_id}/artifacts` | the workspace's artifacts, newest first |
| `GET` | `/artifacts/{artifact_id}` | detail: the body, the files, quiz or flashcard progress, and for a revised copy `revision: {derived_from_document_id, source_name, counts, applied}` |
| `POST` | `/artifacts/{artifact_id}/regenerate` | run the job again; `202`, or `409` while a run is queued or running, with the code `already_generating` unless the artifact is a revised copy, whose refusal has no code yet. A draft re-resolves a recorded `source_scope` without the artifact itself, else replays the recorded ids that still exist, and gives `409` `sources_gone`, "None of this artifact's sources are left.", when none remain. A refine repeats its rewrite without its sources, and gives `409` `rewrite_too_long` when the rewrite no longer fits the selected model ([Refine](#refine)). An image edit repeats its edit on the same base without its sources, and a drawn picture paints its prompt again with none; either gives `409` `needs_image` when no image model is chosen or the chosen one is gone, since any image model edits or redraws ([editing a picture](#editing-a-picture)). A revised copy applies its stored edits to the same input again and asks no model |
| `POST` | `/artifacts/{artifact_id}/refine` | `{instruction}`; the next version, `pending`; `202`; its `409`s are under [Refine](#refine), six of them with a code: `needs_chat`, as for an unavailable format, and five of a refine's own |
| `POST` | `/artifacts/{artifact_id}/image-edit` | `{instruction}`; an image's or infographic's next version, `pending`; `202`; its four `409`s are under [editing a picture](#editing-a-picture) |
| `POST` | `/artifacts/{artifact_id}/revisions/{accept-all\|reject-all}` | a Word revised copy's next version from its newest, every tracked change accepted or rejected; `202`, or `409` for a workbook or deck, a version with no changes, or while a version is being made ([revised copies](#revised-copies)) |
| `GET` | `/artifacts/{artifact_id}/revised-copy/download?variant=changes\|clean&suffix=` | the revised copy as an attachment, named after the source; `404` for `clean` of a workbook or deck ([revised copies](#revised-copies)) |
| `POST` | `/artifacts/{artifact_id}/cancel` | stop a queued or running job; `409` `nothing_running` if nothing is running |
| `GET` | `/artifacts/{artifact_id}/files/{role}` | stream the `primary` or `preview` file |
| `PUT` | `/artifacts/{artifact_id}/quiz-state/{answer\|skip\|retake}` | quiz progress |
| `PUT` | `/artifacts/{artifact_id}/flashcard-state/{mark\|reset\|order}` | flashcard progress |
| `DELETE` | `/artifacts/{artifact_id}` | delete the artifact, its rows and its files; `409` `edited_from` while a later image edit starts from it ([editing a picture](#editing-a-picture)) |

- The artifact routes are keyed on the artifact alone, since a local install has one user. An artifact's `status`, `title` and `error_message` are its document's.
- A prompt is at most 2,000 characters. A podcast brief holds a `language`, a `style`, a `duration` and one or more `speakers`, each with a name, a role and a voice.
- Files are served inline so a viewer can render or stream them, except `text/html` and `image/svg+xml`, which are forced to download so a generated page never runs on the API's origin. `?download=1` sends any file as an attachment.
- The file route ends its transaction before the first byte. The request's session closes only once the file has streamed, and a player reads a podcast for minutes, so holding the write lock that long left every other request failing as `database is locked`.
- Quiz and flashcard progress is stored in `artifact_metadata`, scoped to the artifact's `generation`, so a regenerate starts a clean run.
- There is no manifest route; the viewer reads `GET /artifacts/{id}` and the file stream.
- `DELETE /artifacts/{id}` deletes the document, which cascades the sidecar, its file rows and its chunks, then removes `artifacts/<id>/` after the commit. This is ADR 0003's blob-purge obligation, on this route.

## The image path

- A drawn `image` or `infographic` resolves the `image_gen` selection, and an edit, or a drawing with references, the model that takes a picture in ([below](#which-model-takes-a-picture)). A remote selection loads its connection, which runs the egress check and decrypts the key. An `sdcpp` selection points the same client at the bundled sd-server's loopback URL, with no key and no egress decision, which is what makes an image possible on an offline machine.
- sd-server runs only while Studio needs it, because it keeps a model's weights in memory until it exits. The API answers Electron's poll from the jobs ([`local_image_demand.py`](../../surfsense_local/backend/modules/artifacts/local_image_demand.py)): the chosen model of the image type the oldest processing job needs, read from its recipe, so an edit needs `image_edit` though its format is still `image` or `infographic`; else, for 5 minutes after the last such job ended, the same one, so a second image does not reload it; else nothing, and Electron stops it. A cancel ends the window at once, since sd-server cannot stop a generation, and so does any other Studio job running, since a podcast voices in that memory and a text job loads the chat model into it. The job first gives up the text runtime through the API, held for the whole image, because the two share the graphics card and its writing is done by then: the API lets running replies finish, unloads the text models and keeps local text waiting until the image is drawn, and unloads the speech recognition model, starting no recording's window meanwhile ([admission](local-models/admission.md#the-image-jobs-hold)). Then it waits up to 2 minutes for `/sdapi/v1/sd-models` to name its weights before it posts, and fails with a reason if sd-server never comes up.
- sd-server is launched with each file of the build on its flag and the model's reviewed `image` defaults as its own (`-W`, `-H`, `--steps`, `--cfg-scale`, `--sampling-method`, `--flow-shift`), since a request that carries none of them starts from the launch settings ([`local-models/catalog.md`](local-models/catalog.md)).
- The client posts `{model, prompt}`, and `size` when a shape is asked, to `/images/generations`, falls back once to `/images`, where the shape is `aspect_ratio`, only on `404` or `405`, and remembers the route that worked for the life of the process. A refusal is decided by its status alone, so one whose body is cut off still counts: OpenRouter has hung up partway through the body of a `404`, which failed a comic's pages before ([`image_response.py`](../../surfsense_local/backend/modules/llm/providers/openai_compatible/image_response.py)). Only a success must arrive whole. It accepts `b64_json`, a data URL or a URL, caps the sizes, and checks the bytes against the claimed MIME type ([`connections.md`](connections.md)).
- The `text_gen` model writes first in both formats, except a picture the agent asked for ([below](#pictures-the-agent-asks-for)). The markdown body is the image prompt or the brief, so an image can be found by what it shows.
- A drawn picture is v1 of its own document: the job records `version` and `recipe: {"kind": "draft"}` as a Word draft's, so its edits group under it. Regenerate on it still draws from the sources and replaces v1 in place.
- Every drawing, edit and redraw keeps the exact prompt it sent as `drawing_prompt`, so a later redraw starts from it ([`redraw/`](../../surfsense_local/backend/worker/studio/media/visual/redraw/)).

### Which model takes a picture

One rule picks the model for any job that sends a picture in, an edit or a drawing with references ([`pictures_in/`](../../surfsense_local/backend/modules/llm/pictures_in/)):

1. the `image_edit` selection, when one is chosen: an override, for editing with another model;
2. else the `image_gen` selection, when it takes a picture in;
3. else none, and an edit is drawn again ([below](#editing-a-picture)).

Whether a remote image model takes a picture in is read when it is chosen, from its connection's model list: a model that lists `image` among its `input_modalities` and its outputs, as OpenRouter's do, gets the `image_edit` type beside `image_gen`, as the catalog already gives a model with an image in and out; the choice keeps `takes_pictures` in the selection's `settings`, and another model chosen starts without it. A local model takes pictures when its entry names `edit`. A model chosen unlisted is taken as words only, since a picture it ignores is billed. `GET /llm/pictures-in` answers `{source}`, `edit_model`, `image_model` or `null`, for the app.

### Shapes and references

A drawing can ask for a `shape`, `square`, `portrait` or `landscape` ([`picture_shape.py`](../../surfsense_local/backend/modules/llm/providers/picture_shape.py)):

- **Remote:** `size` `1024x1024`, `1024x1536` or `1536x1024` on `/images/generations` and `/images/edits`; `aspect_ratio` `1:1`, `2:3` or `3:2` on `/images`. A server that refuses one with a `400` is asked once more without it and remembered, separately from `response_format`, since GPT image models refuse that and take a size.
- **Local:** a drawing with a shape goes through sd-server's native `img_gen` with `width` and `height` at the launch's `-W` times `-H` pixels in the shape's proportions, each side a multiple of 64; a drawing with none keeps `/v1/images/generations`.

References are pictures sent with the prompt, so a new picture keeps their characters and style, as a comic's later pages keep page 1's. They go to the model that takes a picture in, as an edit's one picture does: every reference as an `image[]` part of `/images/edits`, or, where a server answers `404` or `405` there, as OpenRouter does, `input_references` of `{type: "image_url", image_url: {url: <data URL>}}` on `/images`, remembered per server; locally, every one in `ref_images`. A refusal there comes before any drawing, so trying the other route bills nothing; a `5xx` or a timeout is never retried. With no model that takes a picture in, the picture is drawn from its prompt alone and keeps `drawn_from_words`.

### Pictures the agent asks for

`surfsense_make_image` ([agent](agent.md#pictures-the-agent-makes)) creates an `image` or `infographic` with no sources, the chat's `chat_thread_id` and the recipe `{"kind": "image_drawn", "prompt"}`, with `shape` and `references` (artifact ids) when asked ([`drawn_images/`](../../surfsense_local/backend/modules/artifacts/drawn_images/), [ADR 0087](../adr/0087-the-agent-makes-pictures-with-its-own-surfsense-tool.md)). The job paints the prompt as written, asking no chat model; an infographic adds Studio's sketchnote style around it ([`media/visual/drawn/`](../../surfsense_local/backend/worker/studio/media/visual/drawn/)). The body is the title and the prompt, so it can be found by what it shows.

It needs only `image_gen`, its Regenerate paints the same prompt at the same shape from the same references, a deleted reference failing it, and Huey never retries it, since each try may be billed. It is v1 of its own document and takes Studio's Edit box like any picture. Every edit keeps its base's chat, from either box, so that chat can still place it. While a script of its chat names a picture, deleting that picture is refused with `placed_in_document`, since the script names it rather than copying it ([`placed_in.py`](../../surfsense_local/backend/modules/artifacts/drawn_images/placed_in.py)).

### Comics the agent binds

`surfsense_bind_comic` ([agent](agent.md#pictures-the-agent-makes)) creates a `comic` with the recipe `{"kind": "comic_bound", "pages": [{"picture", "lines"}], "layout", "direction"}`, naming the pictures it drew in its chat in reading order ([`comic/bound_comic.py`](../../surfsense_local/backend/modules/artifacts/comic/bound_comic.py)). A page still being drawn makes it wait with `waits_for`, as a document does ([`waiting_renders/`](../../surfsense_local/backend/modules/artifacts/waiting_renders/)). The job binds the pictures' own files with the shared binder and asks no model, so it asks for no local image model either. Called again with the comic's `artifact_id`, it makes the comic's next version; a Studio comic keeps no pages, so it cannot be continued that way.

Its pages are never listed: a picture drawn with `comic_page`, every later version of it, and any picture a comic binds keep `comic_page: true`, and `GET /workspaces/{id}/artifacts` leaves them out ([`comic/pages.py`](../../surfsense_local/backend/modules/artifacts/comic/pages.py)), so Studio, mentions and the jobs dialog show the comic alone. A page is not indexed either, and binding takes a page drawn without the mark out of the index, so search finds the comic alone, as it finds a PDF. Its text is its title, each page's drawing prompt, a line every page repeats (its style, its cast) kept once, and the lines set under its pages ([`bound_pages.py`](../../surfsense_local/backend/worker/studio/media/visual/comic_binding/bound_pages.py)): its bubbles are drawn, so the PDF holds no text to read them from. A page still opens by its id from the chat step that drew it. Deleting a comic deletes the pages no other comic binds and no document places, every version of each, newest first ([`unused_pages.py`](../../surfsense_local/backend/modules/artifacts/comic/unused_pages.py)); a page drawn and never bound stays, unlisted.

### Editing a picture

`POST /artifacts/{id}/image-edit` with `{instruction}` (1 to 2,000 characters, as Refine's) makes an image's or infographic's next version from the open version's picture ([`image_edits/`](../../surfsense_local/backend/modules/artifacts/image_edits/), [ADR 0077](../adr/0077-an-image-edit-is-the-next-version.md)).

- It refuses, each a `409` whose `detail` is `{message, code}`: a version still being made (`already_generating`); one whose last run failed or was stopped (`image_version_unfinished`, its own code so the sentence says to edit another version, not refine one); anything but an `image` or `infographic` with a still `primary` picture in PNG, JPEG or WebP, since an edit model does not read the SVG a remote model may draw and `/images/edits` takes no GIF (`not_editable`); and, after those, no image model at all (`needs_image`, "Needs an image model"): with [no model that takes a picture in](#which-model-takes-a-picture), the image model draws it again, so no edit is refused for want of an edit model. Egress to its host being off is refused as any call to a host is, with the egress refusal that asks to allow it ([egress](egress.md)). The check reads the selection and asks no server, which would add a round trip to every edit and could start sd-server only to answer; a model that cannot be reached fails the version with its reason, as a refine's does. `ArtifactRead.image_editable` is true for a ready `image` or `infographic` with a `primary` PNG, JPEG or WebP.
- It creates the next version, `pending`, with the base's title, prompt and `source_document_ids`, and the recipe `{"kind": "image_edit", "instruction", "base_artifact_id"}`, under the `version` keys a refine writes. An image drawn before versions were kept becomes v1 then. The recipe names the base rather than copying its bytes, so a base cannot go while a later version names it: `DELETE /artifacts/{id}`, and the documents route for its document, refuse it with `409` `edited_from`, "A later version is edited from this one: delete the whole document." ([`edited_from.py`](../../surfsense_local/backend/modules/artifacts/image_edits/edited_from.py)). The list deletes a document's versions newest first, each after the last, and an edit is always newer than its base, so it never meets the refusal.
- The job reads the base's own file, so edits chain: editing v3 starts from v3's picture. The instruction goes to the model that takes the picture as written, with no chat model call first ([`media/visual/edit/`](../../surfsense_local/backend/worker/studio/media/visual/edit/)). The body is the base's, then `Edited: <instruction>`, so the version stays findable by what it shows and says how it moved; the file keeps the base's name with the extension of what came back. Every failure ends the job without Huey's retry, as a refine's does.
- **A redraw.** With no model that takes a picture in, the image model draws `<drawing prompt>\n\nChange: <instruction>` at the base's proportions, with no chat model. The drawing prompt is the base's `drawing_prompt`, or, for a picture drawn before it was kept, its recipe's prompt, or its body under the title, so changes add up from version to version. The version keeps `redrawn: true` and its body starts "Drawn again with your change." ([`redraw/`](../../surfsense_local/backend/worker/studio/media/visual/redraw/)). Studio's Edit box says so in its placeholder, "Describe a change: the picture is drawn again", read from `GET /llm/pictures-in`.
- **Remote:** the client posts multipart `/images/edits` with `image`, `prompt`, `model` and `response_format: b64_json`, sent once more without the last if the model refuses it with a `400`, as a generation is ([connections](connections.md)); where the server has no `/images/edits`, the picture goes to `/images` as a reference ([above](#shapes-and-references)); and no `input_fidelity`, which only some GPT image models take ([`image_edit.py`](../../surfsense_local/backend/modules/llm/providers/openai_compatible/image_edit.py)). It reads the answer's `data[]` with the same bounded read, link fetch and MIME check as a generation ([`image_response.py`](../../surfsense_local/backend/modules/llm/providers/openai_compatible/image_response.py)).
- **Local:** inside the same text-runtime hold and model wait as a drawn image, the client posts sd-server's native `POST /sdcpp/v1/img_gen` with `{prompt, ref_images: [<data URL>], width, height, output_format: "png"}` and polls `GET /sdcpp/v1/jobs/{id}` each second, which also looks for a cancel ([`editor.py`](../../surfsense_local/backend/modules/llm/providers/sdcpp/editor.py)). A `failed` job, a `404`, `410` or `429`, or a server that stops answering fails the edit. Steps, guidance and sampler come from the launch, as for a drawn image; the size is the base's own, since an edit model launched at another size would crop or stretch it. sd.cpp picks the reference preset from the model's architecture, so the launch needs no `--ref-image-args`.
- **Why `img_gen`.** At the pinned `master-869-07a85c7`, sd-server's `/v1/images/edits` makes the first upload the `init_image` as well as a reference, and `/sdapi/v1/img2img` takes `init_images`: both re-noise the picture at a strength of 0.75 rather than edit it. `ref_images` alone is how every edit model sd.cpp documents is run.
- **Cancel:** a queued sd.cpp job is withdrawn with `POST /sdcpp/v1/jobs/{id}/cancel`, given 2 seconds, since the text runtime is still held while it is asked. A generating one cannot be (`cancel_generating: false`); the cancel ends the demand at once and Electron stops sd-server, as for a drawn image.
- **Which models edit:** a local model whose entry names `edit`, today FLUX.2 klein 4B, which fills both image slots from one download, so nothing reloads between drawing and editing; or a remote model that takes an image in and gives one out, by its connection's own list or the catalog ([`classifier.py`](../../surfsense_local/backend/modules/llm/catalog/remote/classifier.py)). Settings lists those with an **Image editing** badge beside **Image generation**. Models that can only re-noise a picture, SD 1.5, SDXL, Z-Image Turbo, ERNIE-Image Turbo and LongCat-Image, name no `edit`: they cannot be chosen as the edit override, and a picture they drew is redrawn.

## Known gaps

- A Studio comic keeps only its PDF, so one page cannot be changed: Regenerate draws every page again.
- A page the agent drew and never bound is kept unlisted, until its chat's comic binds it; nothing deletes it.
- An image edit is measured only on klein Q4_0 through the pinned sd-server on a processor, with no graphics card: a photo's layout held, and an infographic's printed lettering held through a colour change and a changed title, 657 to 962 seconds an edit, about twice a draw. Lettering klein drew itself, a sketchnote's, is not measured, and neither is any time on a graphics card or a remote edit model.
- An edit changes the whole picture by instruction; there is no mask or selected region, which sd.cpp and `/images/edits` both take, since drawing one needs its own interface.
- References are measured only on OpenRouter's `/images`, on six models drawing one four-page comic: each held its characters from page 1. OpenAI's `/images/edits` with several pictures, and local references and shapes through sd-server, are not measured; nor is a remote server that takes one picture on `/images/edits` and refuses several.
- The [images guide](../../www/content/docs/v2/guides/images.mdx)'s walkthrough and screenshots still choose a separate model for editing, from before the image model edits.
- A remote model's taking pictures is read when it is chosen; a provider that later starts or stops listing it is not seen until the model is chosen again.
- The [window budget](#the-window-budget) prices a draft's first call. What only some calls add is not priced: a written web page's design guide (6,235 characters, about 2,100 tokens past the prompt it reserves), the failed reply a repair replays, and a podcast segment's recap. On a small window these can leave the reply short or be refused, which fails the job with the context sentence and no retry. Reasoning is not reserved either: Studio turns thinking off, which the local runtime honours and some remote endpoints do not, whose windows are large.
- The budget prices text with admission's estimate, not the model's tokenizer, so scripts it prices at a token a character, such as Cyrillic or Devanagari, are cut further than they need. A long figure list leaves a Word or PDF draft less of its sources' text, since every figure they hold is listed.
- Under an image's hold, a local model no request has seated since the app started has no last window, so its job keeps the 24,000-character ceiling and may be refused.
- A remote model whose window neither its plan nor the catalog states, such as one served by Ollama or LM Studio, keeps the ceiling too, and a refusal past its window fails the job rather than gathering again for the window the refusal names.
- Whether Studio's Web page template is still needed is not measured. The levels that send a model to the written path were set on document tasks; the ladder's models have not written pages yet. If `studio_only` models write pages that pass the structural checks and look right, the template and its three prompts go; if `agent` models fail, the bar needs an HTML case.
- Outside a model call, a cancel stops a job only between steps. The podcast turn being voiced and ingest's parsing and embedding run to their end first, because jobs are threads that cannot be killed; stopping a step in flight means running each job in a process the worker can kill, as a script document's run already is.
- Studio's own PPTX and XLSX scripts run in the runner without asking the user, like Word and PDF; nothing confines their network or file access (below).
- A model not measured still takes the provisional rule ([model capabilities](model-capabilities.md)): a large model served from this computer writes Markdown, and a small remote one writes a script.
- The PDF builder keeps Helvetica for Latin-1 and sets other letters in DejaVu Sans (shipped with matplotlib) or, for Chinese, Japanese and Korean, ReportLab's CID fonts, which are not embedded and rely on the viewer's substitutes. Reading one back has the same dependence: on a computer with no CJK font, pdfium cannot measure a glyph of those fonts and drops a text run with no extent, so a run of one such character is lost and `第1章 概要` reads back as `1 概要`. Studio keeps the Markdown as this builder's body, so that reaches the index only through a script's PDF that uses those fonts, whose body is read back from the file. Arabic and Hebrew are drawn in logical order and Arabic unjoined, and Devanagari and other scripts that need shaping render as boxes: both need a bidi and shaping library the app does not carry. A chart whose labels the matplotlib font lacks (Chinese, for one) is shown as a table.
- A document or analysis script runs with the user's privileges: the runner gives it a clean environment and a time limit, but it can read any file the user can and open network connections ([ADR 0039](../adr/0039-document-scripts-run-without-approval.md)).
- Without Office support, a workbook's formulas show the value the script stored with them, since neither the runner nor Studio's viewer recalculates: xlsxwriter stores 0 unless given one, which the skill tells the agent to pass. Excel recalculates when it opens the file. The render result says the values were not recalculated.
- Only the agent's workbooks are recalculated; Studio's own Spreadsheet format is not.
- A revised copy is cut from its design ([03](../proposals/file-agent/03-editable-artifacts.md)): versions are artifacts, not `artifact_versions` rows, and engines run in the Studio worker's thread, not an engines queue's child process; the agent anchors edits by quote, with no `inspect_document` ids; there are no partial workflows, no per-change accept or reject and no side list of changes, no "With changes (internal)" download and no leak scan, no review record, no reconcile when the original changes, and no "Make a revised copy" in the source viewer. Word headers, footers and footnotes are not edited. An edited workbook is not recalculated until Excel opens it, and a deck has no thumbnails or diff. The report's codes reach the user in English through the agent: the interface does not render them.
- Word and Excel files are drawn with whatever fonts the machine has, so a missing font moves line breaks and can change a page count. No Word was available to compare against: pages were compared with LibreOffice's.
- A canvas has no document structure for a screen reader: text is selectable through the renderer's text layer, but reading order, headings and tables are not exposed.
- `@silurus/ooxml` is young, with one main author, and is pinned to an exact version. A picture watermark is drawn through its luminance effect, and a text one measured at 96 pt, because its own handling of Word's markup garbles them; see ADR 0088.
