# Plugins

A plugin is a remote MCP server whose tools the agent can use. The user connects one of SurfSense's own plugins from the list packaged into the app, a verified or community plugin from the signed [registry](plugin-registry.md), or any server by its URL, in Settings → Plugins, signs in with a key, the license or an account, chooses which of its tools the agent may use and which ask first, and the agent's opencode calls the server itself, under rules SurfSense writes each turn ([agent](agent.md#plugins)). Plugins in Basic threads are still the [proposal](../proposals/plugins/README.md).

**Code:** [`surfsense_local/backend/modules/plugins/`](../../surfsense_local/backend/modules/plugins/), [`surfsense_local/frontend/src/features/plugins/`](../../surfsense_local/frontend/src/features/plugins/)
**Decisions:** [ADR 0051](../adr/0051-plugins-are-mcp-servers-behind-one-tool-gateway.md), [ADR 0053](../adr/0053-plugins-are-listed-in-a-registry-and-third-party-ones-start-off.md)

## SurfSense's own plugins

[`lists/first_party/plugins.json`](../../surfsense_local/backend/modules/plugins/lists/first_party/plugins.json) lists them, packaged into the API with their icons in `icons/` beside it (`bundling/api.spec`), so `GET /plugins/first-party` answers with no network or consent. Each entry names its icon in `icon`, by file name, and the tools its server offers in `tools`, which its page shows before it is connected and the plugin host's tests check against each server ([plugin host](plugin-host.md#tests)); Web Crawl's is the web app's `web.svg`, and Google Maps' its flat vector pin, since the web app's file embeds a 4 MB raster. It holds SurfSense's scraper plugins, one per platform: Google Search, Web Crawl, YouTube, TikTok, Google Maps, Amazon, Walmart and Indeed. Reddit and Instagram are written but left out until they can read anonymously again ([plugin host](plugin-host.md#known-gaps)). Each is its own server at `https://plugins.surfsense.com/<id>/mcp`, served by the [plugin host](plugin-host.md), so the user connects, pauses and mentions each apart, and one consent for `plugins.surfsense.com` covers them all.

- **The check.** Every entry follows the schema both lists share ([`list_entry.py`](../../surfsense_local/backend/modules/plugins/lists/list_entry.py)): its id, an `https` URL with no credentials, `hosts` naming the URL's host and no loopback, and an `access_note` when `access` is `external`. A first-party entry carries no `verification`, its `icon`, when it names one, is a plain file name present in `icons/`, it has an `about` of up to 600 characters, it lists its `tools`, each an MCP tool name once, and the month it was `added` as `YYYY-MM`, and one with `auth: license` sits on `https://plugins.surfsense.com` ([`first_party_list.py`](../../surfsense_local/backend/modules/plugins/lists/first_party/first_party_list.py)). A bad entry fails naming its field, and a unit test checks the packaged list, so it fails CI.
- **Connecting.** `POST /plugins/first-party/{id}`: an id not listed is `404`; one connected already, or whose URL is, is `409 plugin_already_connected`; a host not allowed is `403 egress_disabled`, as below. The server's tools are listed with the license, and the plugin is stored with `source: first_party` and `credential_kind: license`. A `401` or `403` still connects it, its check saying why, since a missing license is the server's to report; any other failure is `502 plugin_unreachable`.
- **The license.** Every request to a license plugin's server carries `Authorization: License <key>`, the key read from the imported license each time and never stored on the plugin ([`plugin_headers.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/plugin_headers.py), [`license_key.py`](../../surfsense_local/backend/modules/license/license_key.py)). Its expiry is not checked here: the server decides. The key goes only to a URL on the plugin host this build reaches; a plugin connected elsewhere is sent no key.
- **A developer's plugin host.** `SURFSENSE_LOCAL_PLUGIN_HOST_URL`, such as `http://127.0.0.1:8000`, moves every listed URL and host on `plugins.surfsense.com` to a plugin host run locally ([`plugin_host.py`](../../surfsense_local/backend/modules/plugins/lists/plugin_host.py)), and the license key with them.
- A custom plugin never takes a first-party id: one named Amazon is `amazon-plugin`.

## Third-party plugins

`GET /plugins/registry` lists the [registry](plugin-registry.md#in-the-app)'s entries, fetched at most every five minutes and only while third-party plugins are allowed; while they are off it answers `third_party_off: true` and fetches nothing ([`routes.py`](../../surfsense_local/backend/modules/plugins/lists/registry/routes.py), [`registry_read.py`](../../surfsense_local/backend/modules/plugins/lists/registry/registry_read.py)). Each entry carries its name, description, author, `verification` and `verified` for a plugin proven to be run by its author, `server_host`, the host every call goes to, and `sign_in_hosts`, an OAuth plugin's other hosts, `access` and `access_note`, `auth_type` with a token entry's `auth_title` and `auth_description`, `hosts`, `homepage`, `privacy_policy`, `about`, `tools` (null when the entry lists none), `added`, `has_icon` and `connected`; the answer carries `fetched_at` and `removed`.

- **Connecting.** `POST /plugins/registry/{id}`, with `{token}` for a `token` entry: third-party plugins off is `403 third_party_off`; an id not listed is `404`; one connected already, or whose URL is, is `409 plugin_already_connected`; any of the entry's hosts not allowed is `403 egress_disabled` naming them all. An `oauth` entry then starts a sign-in, `202` ([below](#signing-in-with-oauth)). Any other lists the server's tools, with the key as `Authorization: Bearer`, refused as a server added by URL is, and is stored with `source: registry`, its publisher and entry, and a key as `credential_kind: token` ([`registry_plugin.py`](../../surfsense_local/backend/modules/plugins/installed/registry_plugin.py)).
- **Removed.** A plugin connected from the registry whose id is in `removed` keeps its row and key, but `list_tools()` leaves it out, and its row carries `removed_reason`. A custom plugin with the same id is untouched.
- A custom plugin never takes a registry id, a removed one included ([`custom_plugin.py`](../../surfsense_local/backend/modules/plugins/installed/custom_plugin.py)).

## Connecting a server

`POST /plugins/custom` with `{url, name, token?}`, in this order:

1. The URL is put in one spelling: scheme and host lowercased, no default port, trailing slash or fragment ([`server_url.py`](../../surfsense_local/backend/modules/plugins/installed/server_url.py)), so one server is never connected twice.
2. A name already in use is `409 plugin_name_taken`, and a server already connected is `409 plugin_already_connected`, each with `name`. A name becomes the id, lowercase words joined by hyphens; `surfsense` is never one, since it is the agent's own server.
3. A server off this computer not on HTTPS is `422 plugin_needs_https`: the agent reaches remote servers only through a TLS tunnel ([agent](agent.md#network)).
4. A host not allowed is `403 egress_disabled` with `hosts` and `purpose: "plugin"`, so the prompt words its question for a plugin's server, and the host is recorded off for Settings › Network ([egress](egress.md)).
5. SurfSense lists the server's tools with the official MCP SDK's client, the key as `Authorization: Bearer`. A `401` to a request with no key, from a server that asks for OAuth, starts a sign-in instead, `202` ([below](#signing-in-with-oauth)). Any other `401` or `403` is `422 plugin_needs_sign_in`; anything else that fails is `502 plugin_unreachable`.
6. The plugin is stored with its key encrypted (`shared/secrets.py`), and every tool it listed starts on.

## Signing in with OAuth

A registry entry with `auth: oauth`, or a server added by URL that asks for it, signs in with the user's account in their browser. Nothing is stored until the sign-in finishes, so an abandoned one leaves no row, token or registered client ([`plugin_sign_ins.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/oauth/plugin_sign_ins.py)).

1. **Discovery.** The server's `401` names its protected resource metadata (RFC 9728), whose first authorization server is the one used; a server with none but `/.well-known/oauth-authorization-server` on its origin is its own ([`oauth_discovery.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/oauth/oauth_discovery.py)). A refusal that names neither is not OAuth.
2. **Consent.** The authorization server's host is asked about before any request reaches it: `403 egress_disabled` with `purpose: "plugin"`. Every request of the sign-in goes through a client that refuses a host not allowed before it leaves ([`consented_client.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/oauth/consented_client.py)), and the host joins the plugin's `hosts`, so readiness and the plugin proxy require it too.
3. **The page.** The MCP SDK's OAuth client runs registration, PKCE and the code exchange ([`sign_in_flow.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/oauth/sign_in_flow.py)). The connect route answers `202` with `{id, plugin_id, authorization_url}` once the URL is ready, within 60 seconds, or `502 plugin_sign_in_failed` ([`start_sign_in.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/oauth/start_sign_in.py)). The screen opens it in the browser and polls `GET /plugins/sign-ins/{id}`, `waiting`, `connected` or `failed` with a sentence; `DELETE` abandons it. A sign-in lives ten minutes in the API's memory, so a restart ends it, and a new one for the same plugin cancels the earlier.
4. **The way back.** The `state` sent is `<port>.<nonce>`, the API's port and the SDK's own state ([`sign_in_state.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/oauth/sign_in_state.py)). `GET /plugins/oauth/callback` answers only a state this API issued; a provider's `error` ends the sign-in, `access_denied` as declined. The tools are then listed with the new token, the plugin stored, and the browser's page says it is signed in or why not ([`callback_page.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/oauth/callback_page.py)).

**Who SurfSense signs in as** ([`sign_in_client.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/oauth/sign_in_client.py)). A packaged app is one public client, `https://plugins.surfsense.com/oauth/client.json`, a client ID metadata document whose redirect is the plugin host's callback page, which forwards the browser to the API's port ([plugin registry](plugin-registry.md#oauth-files)); a server that does not take such documents gets dynamic registration with the same redirect. An unpackaged API, or one with `SURFSENSE_LOCAL_PLUGIN_HOST_URL`, registers dynamically with its own `http://127.0.0.1:<port>/plugins/oauth/callback` (RFC 8252). An entry's `auth.client_id` is used as a client registered in advance, and its `auth.scopes` are asked for. No client secret ships.

**The credential.** The tokens, their expiry, the client signed in as, the token endpoint and the resource indicator are one encrypted JSON blob in the row's credential, `credential_kind: oauth` ([`oauth_credential.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/oauth/oauth_credential.py)). Only the access token leaves the app, as `Authorization: Bearer` ([`plugin_headers.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/plugin_headers.py)); none is logged or returned.

**Refreshing** ([`token_refresh.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/oauth/token_refresh.py)), one at a time per plugin, since providers rotate refresh tokens. Before an agent turn, a token that expires within 30 minutes ([agent](agent.md#plugins)); and a listing the server refuses with `401`, at a check or Refresh tools, is refreshed once and listed again ([`listed_after_refresh.py`](../../surfsense_local/backend/modules/plugins/remote/sign_in/oauth/listed_after_refresh.py)). A refused refresh, or none possible, records `check_failure: sign_in`, and an OAuth plugin so marked is not ready. A token endpoint that cannot be reached, or whose host is off, leaves the sign-in as it was.

**Signing in again.** `POST /plugins/{id}/sign-in` signs the same row in again, so its tool settings stay, reusing the client an earlier sign-in registered when its redirect still matches. A plugin that does not sign in with an account is `422 plugin_not_oauth`.

| `plugin_settings` | one row: `third_party_on` |

## Ready tools

`list_tools()` in [`gateway/listing.py`](../../surfsense_local/backend/modules/plugins/gateway/listing.py) is the one answer to which tools may be used now: a tool switched on, of a plugin switched on and not disconnected, whose hosts are all allowed, not removed from the registry, not an OAuth plugin signed out, and, unless SurfSense publishes it, only while third-party plugins are allowed. `needs_approval()` in [`gateway/approval.py`](../../surfsense_local/backend/modules/plugins/gateway/approval.py) says which ask: a first-party read-only tool never does, a tool that does not say it is read-only and does not say it is harmless (`destructiveHint` absent or true) always does, and any other asks unless set to Always allow.

**Tools added later.** Each listing after the first is recorded by [`recorded_tools.py`](../../surfsense_local/backend/modules/plugins/installed/recorded_tools.py): a new tool starts off, a tool whose description changed or whose annotations became less safe is switched off, and a tool the server dropped is deleted. The agent's turn lists again at most every five minutes ([agent](agent.md#plugins)).

## Checks

Every listing of a server is a check, recorded on its row ([`plugin_check.py`](../../surfsense_local/backend/modules/plugins/installed/plugin_check.py)): connecting, the agent's listing before a turn when the last check is five minutes old ([agent](agent.md#plugins)), and **Refresh tools**. One that answers records its tools; one that fails keeps the tools last recorded and says why: a `401` or `403` as `sign_in`, unless its body's `reason` is one of [contract 2](../contracts/02-scraper-api-auth.md)'s, `missing_license`, `expired`, `revoked` or `invalid`, which become the license failures; anything else is `unreachable`. An OAuth plugin's `401` is refreshed and listed once more first ([above](#signing-in-with-oauth)).

A tool switched off by a check, because it is new or its description or annotations changed, is marked `added` or `changed`. Switching it on clears the mark: the user has allowed it as it now reads.

| `GET` | `/plugins/registry` | The registry's plugins, each with `connected`, and the removed ones |
| `GET` | `/plugins/registry/icons/{id}` | An entry's verified icon, from the copy held |

| `GET` | `/plugins/oauth/callback` | Where the browser comes back from the provider |
| `POST` | `/plugins/{id}/sign-in` | Signs an OAuth plugin in again, keeping its tool settings |

| `POST` | `/plugins/{id}/check` | Lists the server again and records the check |
| `PUT` | `/plugins/{id}/key` | `{token}`: the server lists its tools with the new key first, and only a key it accepts replaces the old one, recorded as a check; the tool settings stay. A refusal is the same `422` or `502` as connecting |

| `GET` / `PUT` | `/plugins/third-party` | `{allowed}` |

## Settings → Plugins

[`plugins-settings.tsx`](../../surfsense_local/frontend/src/features/plugins/plugins-settings.tsx), under Settings, says plugins work in Agentic threads and has two tabs, **Yours** and **Browse**, with **Add custom plugin** beside them and nowhere else. It opens on Yours when a plugin is connected, otherwise on Browse, chosen once when the list first loads.

- **Yours** ([`your-plugins.tsx`](../../surfsense_local/frontend/src/features/plugins/yours/your-plugins.tsx)) is a table of connected plugins, Plugin, Type and Status ([`connected-plugins-table.tsx`](../../surfsense_local/frontend/src/features/plugins/yours/connected-plugins-table.tsx)). Type is "By SurfSense", "Third-party" or "Custom" for a server added by its URL. Status is one state, the first that holds ([`plugin-status.ts`](../../surfsense_local/frontend/src/features/plugins/yours/plugin-status.ts)): "Disconnected", with **Connect** in the row ([`connect-plugin-button.tsx`](../../surfsense_local/frontend/src/features/plugins/details/connect-plugin-button.tsx)), "No longer listed", a failed check ("Couldn’t connect", "Signed out", "Needs a new key", or a refused license), "Third-party plugins are off", "Off", "New tools", then "On". Each row opens the plugin's details. With nothing connected it says so, with **Browse plugins** and **Add custom plugin** ([`no-plugins-connected.tsx`](../../surfsense_local/frontend/src/features/plugins/yours/no-plugins-connected.tsx)).
- **Browse** ([`browse-plugins.tsx`](../../surfsense_local/frontend/src/features/plugins/browse/browse-plugins.tsx)) holds **By SurfSense**, from the first-party list ([`first-party-plugins.tsx`](../../surfsense_local/frontend/src/features/plugins/browse/first-party-plugins.tsx)): each plugin with its logo, its description, "License required" where `access` is `license`, and **Connect**, or "Connected"; connecting ends in a toast wherever it starts, Browse, Add custom plugin, Connect on a disconnected plugin in Yours, a key or a sign-in: "{plugin} connected", including once an account's sign-in finishes in the browser, or "Couldn’t connect {plugin}" with the reason in the app's words and Report issue ([`connect-toasts.ts`](../../surfsense_local/frontend/src/features/plugins/connect-toasts.ts)). Then **Third-party** ([`third-party-plugins.tsx`](../../surfsense_local/frontend/src/features/plugins/browse/third-party-plugins.tsx)), its header holding **Allow third-party plugins**, off by default. Turning it on first asks, saying other people run those servers, what a tool is sent goes to its publisher, and SurfSense does not review changes to them; turning it off asks nothing. While it is off the section is one sentence; while it is on it holds the registry's list once they are allowed ([`registry-plugins.tsx`](../../surfsense_local/frontend/src/features/plugins/browse/registry-plugins.tsx)), dated "Updated" with `fetched_at`. While `plugins.surfsense.com` is off it says the list comes from there, with **Allow**, which raises the egress prompt on the click rather than at load. Each entry shows its icon or its name's first letter ([`plugin-icon.tsx`](../../surfsense_local/frontend/src/features/plugins/plugin-icon.tsx)), name with a Verified checkmark or a Community badge beside it, its description, "By" its author, an `external` entry's note, and **Connect**, or "Connected". A `token` entry's Connect opens a dialog for the key, labelled in its publisher's words ([`registry-key-dialog.tsx`](../../surfsense_local/frontend/src/features/plugins/browse/registry-key-dialog.tsx)).
- **Icons.** Each of SurfSense's plugins and each registry plugin shows the icon beside its list; any other shows the first letter of its name ([`plugin-icon.tsx`](../../surfsense_local/frontend/src/features/plugins/plugin-icon.tsx)).
- **Add custom plugin** opens a dialog with Name, Server URL and an optional Key, and switches to Yours once the plugin is connected; connecting from Browse stays on Browse. Each refusal is shown in the app's words by its `code` ([`refusal-message.ts`](../../surfsense_local/frontend/src/features/plugins/refusal-message.ts)); a host not allowed raises the egress prompt and retries once allowed. While third-party plugins are off, a custom plugin's details say "Not used until third-party plugins are allowed".
- **A sign-in** started by Connect, Add custom plugin or Sign in again opens the provider's page in the browser and shows "Waiting for sign-in…" with Cancel, polling each second until it connects or fails, "The sign-in didn’t finish. ([`use-plugin-sign-in.ts`](../../surfsense_local/frontend/src/features/plugins/sign-in/use-plugin-sign-in.ts), [`sign-in-progress.tsx`](../../surfsense_local/frontend/src/features/plugins/sign-in/sign-in-progress.tsx)). - **A plugin's public page** opens only from its entry in Browse, in place of the list, with **Back** ([`plugin-public-page.tsx`](../../surfsense_local/frontend/src/features/plugins/public-page/plugin-public-page.tsx)). ## Known gaps

- The scraper plugins' entries point at `plugins.surfsense.com`, which is not deployed, so connecting one fails as `502 plugin_unreachable` outside a developer's local plugin host.
- An agent turn names a license plugin it could not use as needing sign-in, not as needing a license ([agent](agent.md#plugins)).
- Only remote MCP servers, reached over HTTP. A local server started by a command, such as `npx` or `uvx`, cannot be added; whether it should be is an [open question](../proposals/plugins/README.md#open-questions).
- OAuth sign-in has been tried only against a stand-in authorization server, never a live provider.
- A packaged app's browser comes back through `plugins.surfsense.com/oauth/callback`, which is not deployed; the tests stand in for its forward by calling the API's callback themselves.
- A failed sign-in reads "The sign-in didn’t finish" whatever the cause; the API's `message` saying why is not shown.
- A server added by URL whose authorization server is on another host raises a second consent prompt, for that host, after the one for the server's own.
- A removed plugin's reason shows only on its connected row; the Third-party list leaves removed entries out and does not show `removed`.
- A check runs at connect, before an agent turn and on request, never on a schedule, so a server that went down is seen only then.
- No activity view: a plugin's recent calls are kept in each thread's opencode session, and the screen does not gather them yet.
- Plugins reach Agentic threads only; Basic threads get none until the chat engine's router step ([proposal](../proposals/plugins/core/03-engines.md#the-chat-engine-later)).
