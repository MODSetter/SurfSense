# ADR 0055: A chat's mode is chosen per chat and kept, and only a technical gate, never a measured score, keeps a model out of Agentic

- **Status:** Accepted
- **Date:** 2026-10-08
- **Source:** [PR 2207, "What changes"](https://github.com/MODSetter/SurfSense/pull/2207), [model capabilities L45–55](https://github.com/MODSetter/SurfSense/blob/f887af1044d0eade9b97b10fea68c24970ea4229/docs/architecture/model-capabilities.md#L45-L55)

## Context

A chat is Basic (Q&A), the chat engine's retrieval answers with Studio beside it, or Agentic, the [agent](../architecture/agent.md). [#2207](https://github.com/MODSetter/SurfSense/pull/2207) shipped the choice, and with it the measured capability list: 270 rows saying what each model did in the Agentic tests ([model capabilities](../architecture/model-capabilities.md)). Three things then had to be decided: what makes a model eligible for Agentic at all, what a new chat starts in, and how far a measurement reaches.

The measured list is screening evidence, not a licence. Its rows are one run per case on OpenRouter's default routing or Anthropic's compatibility layer, 51 of them `assumed` flagships the sweep never ran, and every row was measured on a provider's host only. A pass taken there says nothing reliable about the quantized copy a user runs at home, and a pass/fail bar is too coarse to decide what a user may ask for. The file-agent proposal had planned the opposite model — its ADR 0044 entry read "What a model may do comes from a reviewed, measured capability manifest" — and [#2220](https://github.com/MODSetter/SurfSense/issues/2220) asks for what was built to be recorded and that entry corrected.

## Decision

- **The mode is per chat.** Basic (Q&A) and Agentic are chosen in the composer when a chat is opened, and a chat keeps the mode it opened in (`ChatThread`'s row stores it). In an open chat the switch shows that mode; picking the other one opens a new chat in it. The choice is per chat, never a setting of the model or the workspace.
- **Every model may run Agentic; only a technical gate keeps one out.** The gates are facts about running the agent, never a score: `agent_not_installed` when no opencode is staged; `tool_calls_unsupported` only when tool calls are explicitly reported no — the remote catalog's `tool_call: false` under the connection's catalog provider, or llama-server not reporting `supports_tool_calls` for a local model's template; `window_below_floor` when a stated context window is under 32,768 tokens, the smallest the agent runs at ([`agent_gate.py`](../../surfsense_local/backend/modules/llm/capability/agent_gate.py)). A catalog that says nothing, and a runtime that cannot be read, allow Agentic. A model with a low measured score is offered Agentic with its score shown, not refused.
- **The default comes from the measurement and the host it was made on.** The mode the user last chose for a new chat on that model wins. Otherwise a new chat starts Agentic when the row holds at an agent level (`agent`, or `agent_limited`, "may need nudges") on the host it was measured on — every row today is remote — and Basic (Q&A) otherwise, including for a local copy of a model that passed and for anything unmeasured. A gated Agentic defaults to Basic (Q&A) ([`new_chat.py`](../../surfsense_local/backend/modules/llm/capability/modes/new_chat.py)). Issue #2220 words this as "Agentic for a model measured at `agent`"; the implementation and [model capabilities](../architecture/model-capabilities.md#the-modes) give `agent_limited`, near the bar, the same default. This record follows the code.
- **A measurement speaks only for where it was made.** A pass holds only where the row was measured: a copy served from the user's own machine or network of a model that passed on a provider's host is `not_measured`, and the switch says "Local copy" with that host ([`resolve.py`](../../surfsense_local/backend/modules/llm/capability/resolve.py)). A failure holds everywhere, since a copy of one's own is the same model or a smaller one. An `assumed` row — an expensive flagship the sweep chose not to run — is an expectation, carries the reason `assumed`, and is never shown or written as a test result. The list records for each row its suite, version, date, host and pass counts; the interface words each reason from them.

## Consequences

- Every chat model can reach Agentic, so a model the ladder never ran is not locked out by missing evidence. The cost is that a model which handles tools badly fails at run time: a gated request is refused with a coded `409`, an opencode that does not start with `503`, and a gate the selection could not foresee (such as a local model's template) disables Agentic for that model until restart.
- Scores steer defaults and labels, never permissions. The measured level decides only what a new chat starts in and what the switch says beside Agentic ("Passed 2 of 8 Agentic tests…", "Not tested…", "A local copy may do worse.", "Not run: SurfSense expects this expensive flagship model to pass.").
- Honest scope is shown instead of inherited confidence: a local copy keeps "Local copy", an unmeasured model keeps "Not tested", and an assumed flagship keeps "Expected to pass" — the assumption is labelled, never dressed up as a run.
- The remembered per-model choice (`chat_modes`) overrules both the score default and its changes; only a pick the user made is remembered, so turning a developer switch off or a later measurement still decides for a model the user never picked for.
- `SURFSENSE_LOCAL_AGENT_UNTESTED_MODELS=1` defaults Agentic for every model the user has not picked for and lifts the window floor; a stated no on tool calls, or no opencode, still keeps Agentic out.
- The file-agent proposal's planned ADR 0044 entry is reworded: what a model may do comes from the technical gates and the user's per-chat choice, and a reviewed, measured manifest is evidence for defaults and labels only.
