title: See and control what leaves your computer
description: Check where SurfSense can send data in Settings › Network, block a destination, and answer the question SurfSense asks first
---

import { Step, Steps } from 'fumadocs-ui/components/steps';

<GuideVideo slug="privacy-network" poster="/guides/privacy-network/poster.webp" title="Unticking a site in Settings › Network, then the question SurfSense asks before it reaches that site" />

Nothing leaves your computer until you allow where it goes. Every place SurfSense can send data is a destination, such as a model provider, a plugin's server or a site, and each one starts off. See [Privacy](/docs/v2/privacy) for what each destination gets.

<Steps>
<Step>

### Open Settings › Network

Open **Settings**, then **Network**. It lists every destination SurfSense knows, with its host and its last call. A ticked destination is allowed. **App updates** and **Usage statistics** follow your answers from when you set SurfSense up.

![Settings › Network, listing each destination and its last call](/guides/privacy-network/01-network.webp)

</Step>
<Step>

### Untick one to block it

Untick a destination to block it outright: the next call to it is refused before it leaves your computer.

![A site unticked in Settings › Network](/guides/privacy-network/02-blocked.webp)

</Step>
<Step>

### Answer the question

The next time you do something that needs a destination that is off, such as adding a page from that site, SurfSense asks first and says what the destination gets. **Allow** turns it on. **Cancel** leaves it off, and nothing is sent.

![The question SurfSense asks before it reads pages from a site](/guides/privacy-network/03-ask.webp)

</Step>
</Steps>

Work that runs on its own never asks: a Studio job that needs a destination that is off fails with the reason, and asks the next time you do it yourself. Your own computer is not a destination, so a model server on it, such as LM Studio or Ollama, needs no permission.
